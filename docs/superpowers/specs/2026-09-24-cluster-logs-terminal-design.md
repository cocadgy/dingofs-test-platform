# 集群日志与管理员网页终端设计

日期：2026-09-24
状态：已确认并实施；最终接口与使用方式见 docs/REMOTE_ACCESS_ACCEPTANCE.md。

## 目标与范围

在集群详情中直接排查服务日志，并让 admin 在网页中连接目标机器进行交互操作。首版包括主机别名、日志文件列表/末尾读取/实时追踪/关键词过滤/下载、管理员网页 SSH 终端。沿用现有机器凭据、主机指纹校验和创建者权限。

不包含普通用户完整终端、容器内终端、自动执行诊断命令、文件上传、全盘文件浏览或集中日志存储。日志功能读取宿主机上的服务日志目录；服务日志目录为空或不可访问时明确提示，不改用猜测路径。

## 现有基础

- `dingo cluster status -sv` 已采集服务 ID、角色、Host、Log Dir。
- 当前 Host 只与机器地址精确匹配；`dingo126` 与 `172.30.14.126` 无法关联。
- 后端已有 Paramiko、加密 SSH 密码、主机指纹确认和用户切换流程；既有有界查询不能直接当作长期交互终端使用。
- 当前部署为单个 API 实例；Nginx 尚未配置专用 WebSocket 转发。

## 1. 主机与机器资源关联

机器登记/编辑增加“主机别名”列表，例如连接地址仍为 `172.30.14.126`，别名增加 `dingo126`、`dingo126.novalocal`。

使用统一的主机标识表登记地址与别名，均关联机器 ID。主机名忽略大小写和末尾点，IP 使用规范化形式；保留现有地址+端口唯一约束。跨机器相同标识允许保留，以兼容现有同地址不同端口资源，但解析时必须唯一匹配：

1. 服务 Host 匹配所有未归档机器的连接地址和别名。
2. 恰好匹配一个机器 ID 才建立关联；没有匹配显示“未匹配机器资源”。
3. 多个机器匹配显示“匹配冲突”，不选择第一个，不通过 DNS 推断；提示调整别名或资源登记。
4. 保存别名时提示已有冲突；别名不改变 SSH 连接地址、凭据或主机密钥信任范围。
5. 仅机器创建者和 admin 可编辑别名。更新机器地址、端口、别名或凭据增加 revision，使旧连接授权失效。

为已有机器回填地址标识；别名初始为空。既有服务主机跳转也改用同一解析规则。

## 2. 日志查看交互

服务表每行增加“查看日志”；打开集群下独立日志详情页，支持返回原服务列表。页头固定展示集群、服务 ID、角色、目标机器/IP、读取用户和日志目录，避免混淆节点。

- 首次只列出该服务日志目录下的文件，展示文件名、大小和修改时间，按修改时间倒序；不默认递归扫描目录。
- 选择文件后默认读取末尾 500 行；可选 100/500/1000 行，每次响应上限 1 MiB，超限明确标记截断。
- 点击“实时追踪”订阅新内容；“暂停”停止订阅并保留当前缓冲，再次追踪从记录的位置继续，若文件轮转或历史不可补齐则显示缺口提示。
- 浏览器缓冲上限 5000 行或 5 MiB，先到哪个按哪个淘汰旧内容，并提示已截断。
- 关键词采用字面量匹配，仅过滤当前已加载/实时进入缓冲的内容，不宣称检索了整个历史文件。
- 下载默认提供“下载当前内容”；另可下载单个远程文件（首版上限 100 MiB）。远程下载固定读取开始时的文件长度，不无限追随增长；超限拒绝并说明大小，不静默截断。
- 日志轮转、文件截断、删除、权限不足或主机失联均显示独立状态；跟踪按文件名重新打开合法的新文件，并提示切换事件。

日志内容按文本渲染，ANSI 控制序列不作为浏览器指令执行；不使用终端组件渲染普通日志。

## 3. 日志权限与读取身份

普通用户必须同时具备集群及目标机器的创建者权限，admin 可访问全部；这避免使用别人登记的 SSH 凭据读取节点文件。其他成员仍可查看集群状态和已展示的目录，但不能读取日志正文。

后端依据集群 ID、服务 ID和最近成功状态快照解析目标机器与日志目录。浏览器不能指定任意 host、SSH 用户或绝对路径。文件列表返回服务端文件标识，后续读取/下载重新校验其集群、服务、目录和机器 revision。

连接使用目标机器保存的 SSH 登录用户；日志读取默认使用集群的执行用户，与该用户不同则沿用免密 sudo 优先、需要时临时认证的流程。该用户在目标机器不存在或无法读取时明确报错，不自动改成 root。

远端读取采用固定、只读辅助程序及结构化参数，禁止将文件名、关键词拼入 shell。文件必须是普通文件；拒绝设备、FIFO、socket 和目录遍历。允许常见“最新日志”符号链接，但解析后的文件必须仍在服务日志目录内。实现必须通过目录文件描述符逐级受限解析并固定已打开的文件身份，不能只检查一次 realpath 后再按原路径打开；文件轮转时重复同样校验。

读取前校验服务目标、日志目录、机器 revision、账号权限及登录会话；活动订阅定期重查。快照中的日志目录变更后关闭旧订阅并提示重新选择。

## 4. 管理员网页 SSH 终端

集群详情提供“打开终端”：选择管理机器或已唯一匹配的服务机器。首版只允许 admin，后端独立校验，不能通过普通日志会话升级成终端。

连接确认框明确显示机器名、IP、端口和 SSH 用户。使用该机器登记的 SSH 用户启动交互式 PTY，不自动切换 root、不自动执行 dingo 或 cd 命令；管理员可自行输入 sudo、su、cd、tail 等命令。完整终端具有该系统用户的真实权限，包括访问同机其他集群，不能描述为受限于当前集群的命令行。

终端在平台内的新标签页打开，提供连接状态、尺寸自适应、复制/粘贴和断开按钮。支持 Ctrl+C 等标准终端输入；远程 OSC 剪贴板写入默认关闭。断线不自动重连、不重放输入；重新连接需要用户主动操作。

终端可使用成熟的浏览器终端组件，实施时锁定依赖版本并验证许可证及现有 CSP 兼容性。运行时资源随平台打包，不从第三方 CDN 加载。

## 5. 会话与连接生命周期

HTTP 用于授权、日志文件列表、有限读取与下载；WebSocket 用于日志追踪和交互终端。两个会话类型具有不同的后端协议：日志会话绝不接受 shell 输入或 PTY 请求。

创建会话使用现有登录 Cookie 与 CSRF 校验。WebSocket 仅接受同源连接，并在升级前校验登录、Origin、会话类型和资源权限；会话 ID 本身不是访问凭据，不把 SSH 密码、登录令牌放进 URL。

数据库保存会话元数据：操作者、登录会话 ID、类型、集群/服务/机器、资源版本、创建/结束时间、状态及关闭原因，不保存密码、终端输入、输出或日志正文。短期认证挑战沿用既有账号提示与尝试上限，密码仅在执行进程内存中使用。

SSH 和流读取由可终止的受监督工作进程执行，不阻塞 API 事件循环。输出队列有上限：终端不能持续丢弃内容后假装完整，应在消费过慢时断开；日志可丢弃最旧缓冲但必须提示缺口。退出、页面关闭、主动断开及超时都关闭 channel、SSH 和工作进程。

建议首版默认值（可配置）：

| 限制 | 默认值 |
| --- | --- |
| SSH 连接超时 | 15 秒 |
| 单次文件列表/尾部读取 | 30 秒 |
| 单个下载最长时间 | 120 秒 |
| 终端无用户输入的空闲超时 | 15 分钟，命令输出不重置该计时 |
| 单次终端或追踪最长连接时间 | 2 小时 |
| 每用户同时打开的终端 | 2 个 |
| 每用户同时追踪的日志 | 4 个 |
| 每台机器长期 SSH 连接 | 4 个 |
| 登录与资源权限重查 | 每 5 秒 |

用户退出、禁用、删除、重置密码或权限撤销后，在下一次校验周期内关闭连接。资源归档、revision 改变或主机密钥异常同样终止连接。首次主机信任必须通过原有指纹确认流程，禁止自动接受。

首版按现有单 API 实例实现连接路由；数据库租约防止并发配额越界。API 重启将未结束会话标记中断，不恢复终端；以后扩展多实例需要连接路由或共享会话网关，不能直接扩容后假定连接会自动迁移。

Nginx 增加专用 WebSocket Upgrade/Connection 转发、流式路径关闭响应缓冲，以及和心跳协调的读取超时。沿用部署现有的 HTTP/HTTPS 协议生成 ws/wss 地址。

## 6. 建议接口

- `PATCH /machines/{id}`：增加 aliases 字段，仍遵循创建者权限和 revision 校验。
- `GET /clusters/{id}/services/{service_id}/log-files`：受限文件列表。
- `POST /clusters/{id}/services/{service_id}/log-read`：按文件标识读取有限尾部内容。
- `POST /clusters/{id}/services/{service_id}/log-downloads`：验证权限并创建有界下载，返回同源下载标识；下载时再次校验身份。
- `POST /remote-sessions`：创建 log-follow 或 terminal 会话；服务端推导机器/用户/日志路径，终端管理员可从允许目标中选择机器 ID。
- `POST /remote-sessions/{id}/authenticate`：仅处理未建立 SSH 的短期密码挑战。
- `GET /remote-sessions/{id}`、`DELETE /remote-sessions/{id}`：查看状态/关闭自己的会话，admin 可关闭全部。
- `WS /remote-sessions/{id}/stream`：日志仅接受暂停/心跳；终端接受有界输入、resize、心跳。服务端严格按会话类型校验消息。

以上为接口边界，最终 DTO 在实施计划中细化。所有路径、文件和目标校验在服务端重复执行，不能依赖前端下拉框。

## 7. 审计与验收

审计连接/断开、用户、集群、服务、机器、动作、时间和结束原因；记录日志下载的文件标识与字节数。首版不录制终端输入或完整内容，避免保存 sudo 密码和其他秘密，也不宣称具有逐条命令审计能力。

必须验证：

1. 别名正确关联，未匹配与多匹配时阻止连接；机器更新使旧授权失效。
2. 普通用户可读自己集群且自己机器的日志，其他成员无法越权；admin 可读全部；终端仅 admin。
3. 日志目录约束、符号链接逃逸、路径竞争、特殊文件、异常 UTF-8 和超长行处理。
4. 末尾读取、字面量过滤、缓冲截断、轮转、暂停恢复和固定长度下载。
5. 普通日志会话不能执行命令；终端确认取消时不创建 SSH 连接。
6. 终端输入、resize、Ctrl+C、断线、超时、慢消费者及子进程回收。
7. 账号/会话撤销、跨用户会话访问、跨源 WebSocket 及主机指纹变化。
8. 现有机器、集群发现、启停、topology.yaml 和权限回归。

自动验证使用隔离数据库、本机 SSH 测试服务与临时日志目录，不在真实 DingoFS 节点执行测试命令。完成后再由用户按指定节点进行手工验收。
