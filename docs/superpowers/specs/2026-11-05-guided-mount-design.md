# 挂载文件系统引导设计

## 目标与范围

在“开始”中提供与创建缓存组一致的四步挂载引导。一次选择一个文件系统，支持多台机器、每台多个客户端；复用资源操作鉴权、认证挑战、操作记录和结果展示。不自动卸载已有挂载，不修改现有客户端，不把远端未知结果当作可安全重试。

用户已确认四步流程：选择集群和文件系统 → 选择程序来源 → 选择机器并配置参数 → 检查并挂载。

## 实现方式

采用独立 GuidedMountFlow 页面、复用已有资源执行服务。仅包装现有单机表单无法满足多机检查和安全重试；从头实现独立 SSH 执行服务会重复权限和审计逻辑，因此不采用这两种方式。

## 页面与交互

1. 实时选择集群、文件系统。集群展示名字、管理机器名、IP、执行用户。过滤名称包含 DELETE 的文件系统。提供添加集群、创建文件系统的子引导，完成后返回并选中新资源。
2. 程序来源统一选择默认、指定 TAG、目标机器已有目录。TAG 复用镜像列表并固定 digest；解析和校验失败不得静默回退默认程序。指定目录不下载、不覆盖文件。
3. 机器一行一台，复选框靠左。每台独立填写执行用户、客户端数量（默认 1）、挂载路径、子目录（默认 /）、缓存与日志目录、缓存组、RDMA、客户端参数。指定目录模式逐机填写 dingo-client 所在目录。数量大于 1 时沿用 mount_instances 的 -001、-002 编号，检查页展示最终路径；缓存与日志目录也隔离。RDMA 从各机器采集信息选择。全部可配置参数可见，常用展开、其他折叠；支持加载、保存模板及显式复制参数。
4. 展示最终配置，点击检查并挂载后逐机检查 SSH、执行用户、程序、目录、已有挂载、端口、文件系统及缓存组；检查计划固定参数后执行，不允许前端更改已检查目标。按机器、用户、客户端展示命令与结果。成功项保留，失败项重试前核验实际状态，未知状态不盲目重跑。

新勾选机器继承第一台配置的通用参数，不复制机器身份、端口、挂载路径和程序目录；RDMA 设备重新匹配。无机器时进入添加机器子引导并返回。离开未完成流程有确认；草稿按用户隔离，不保存密码；新建任务清除旧任务引用，不能直接跳到旧完成页。

## 后端约束

现有 mount.create 支持单机 count、模板、mount_options 和 RDMA。新增多机计划与重试能力必须保持原请求兼容。计划在服务端完成权限、路径重复、参数及端口校验；重试关联原任务，不接受前端伪造成功/失败列表。使用现有二进制下载与校验机制的通用部分，为 dingo-client 增加明确的文件选择和版本检查，不能误用 dingo-cache。

目录不存在时按已确认缓存组策略创建，必要时 sudo，仅授权本次明确创建的目录给执行用户，不递归修改已有目录或覆盖已有内容。已有挂载点拒绝重复挂载。网络断开后复用请求 ID 查询结果，不生成重复任务。

## 验收与发布

覆盖步骤切换、子引导返回、草稿隔离、TAG 失败、不同机器路径、参数继承、RDMA 校验、多客户端目录隔离、权限拒绝、重复提交、部分失败和安全重试。使用受控模拟 SSH，不在共享机器上自动挂载测试。只提交本功能文件和相关补丁；排除工作区已有未完成修改。构建验证后按用户惯例提交并部署。
