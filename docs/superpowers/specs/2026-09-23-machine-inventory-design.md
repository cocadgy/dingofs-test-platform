# 机器 SSH 密码与硬件信息采集

日期：2026-09-23
状态：功能范围已确认，详细设计待评审

## 用户目标与范围

管理员在机器资源中配置 SSH 用户对应密码，通过“更新机器信息”按钮收集并展示 Linux 机器的 CPU、内存、磁盘和网卡信息。普通用户可查看结果。继续使用已有机器资源、权限、版本冲突与审计机制，不部署采集 agent，不执行集群启停操作，不自动安装远端依赖。

本次为现有平台新增 SSH 采集能力。此前用户管理、密码长度及部署地址的未提交修改必须保留。

## 实现选择

采用后端 SSH 库连接并执行固定只读采集脚本。相比 shell 调用 sshpass，密码不会进入进程命令行；相比 agent 或任务队列，单机手动更新不需要额外常驻组件。采用 Paramiko 和 cryptography；依赖版本在实施时核对官方文档并锁定。

首版每次更新一个机器，同步请求有明确总时限；不提供任意远端命令输入，不增加批量更新及定时任务。

## 密码配置

机器创建、编辑表单增加 SSH 密码输入框。密码可选，已有资源无需补填即可升级；未提供可用认证配置时采集明确提示需配置密码。原 credential_ref 字段保留，本次不将字符串引用冒充已实现的凭据仓库。

密码原样处理，不去除前后空格。创建时空值表示未配置；编辑时缺省或空值表示保留原密码。独立“清除已保存密码”操作显式清除，避免留空误删。

机器记录新增可空密文字段，使用 Fernet 认证加密。密钥通过 PLATFORM_CREDENTIAL_ENCRYPTION_KEY 注入，仅保存在部署配置中，不入库、不写入版本库。未设置密钥时平台仍可管理普通资源，保存/使用密码时报明确配置错误；不得临时生成不持久的密钥。提供密钥生成及备份说明，丢失密钥须重新录入密码。

API 输出采用白名单，只有 has_ssh_password 布尔值，不返回明文或密文。现有通用序列化必须调整，编辑逻辑不得从输出中反推密码。审计仅保存字段名；错误日志不得包含密码、认证对象或原始请求体。高级 YAML 不接受密码。

## SSH 连接

使用机器 address、ssh_port、ssh_user 和解密后的密码，禁用意外的 SSH agent/本地密钥回退。通过只读挂载的 known_hosts 校验主机公钥：未知或变化的主机密钥拒绝连接，返回对应原因。运维说明提供指纹核验与 known_hosts 配置步骤，不自动无条件信任未知主机。

连接、认证及读取均受控制器单调时间的总截止时间约束，默认总计 30 秒；输出上限 1 MiB；所有分支关闭 channel/transport/client。前端等待状态禁止重复点击。服务端每台机器仅允许一个有效采集，重复请求返回冲突；采用短事务中的采集令牌及到期时间，避免进程崩溃留下永久锁。

## 采集内容与口径

- CPU：型号、逻辑 CPU 数、可获取的物理核数；虚拟化环境不能确认的物理核数标为未知。
- 内存：/proc/meminfo 中的 MemTotal，按字节保存并按 GiB 展示。
- 磁盘：块设备名称、类型、容量、型号、是否旋转；逐项展示物理 disk 类型设备，不把分区、LVM、RAID 映射重复加总为物理容量。挂载文件系统单独展示挂载点、来源、总量及可用量，不将 bind mount 等重复加总。
- 网卡：名称、MAC、IPv4/IPv6、状态、MTU、可读取的链路速率；RDMA 从 sysfs 获取设备、端口及网络接口映射，不依赖厂商管理工具。

远端固定脚本使用 Linux /proc、/sys 及 lscpu、lsblk、ip、df 等常见命令；不要求 sudo 或远端 Python。命令输出受限，并由后端分别解析；缺少单项工具或权限时记录该项不可用，不填 0 冒充真实数值。连接失败与完全无法采集为失败；部分可用为 partial，并列出缺失项。实现需覆盖常见 util-linux/iproute 输出差异与恶意或畸形输出。

## 存储与并发

机器新增结构化 hardware_info（带 schema_version）、last_attempt_at、last_success_at、collection_status、collection_error，以及短期采集令牌/到期时间。保留最近一次成功快照；部分结果保存于单独的最近尝试结果中，页面明确标注，不覆盖旧成功值造成混淆。

采集开始读取 SSH 配置和机器 revision，网络阶段不持有数据库事务或 inventory 全局锁。结束时短事务校验令牌和原始 revision：期间连接信息或资源状态发生变更则不提交过期快照，提示重新采集。归档机器禁止采集。采集结果不覆盖 physical_id 或用户标签。

迁移只增加可空/有默认值的字段，旧机器、关联关系和历史记录保持有效。

## API 与页面

现有机器创建/编辑接口接受 ssh_password 和明确的清除动作，并保持管理员、CSRF、版本检查。

新增 POST /api/v1/machines/{id}/refresh-hardware，管理员可调用，包含 base_revision。成功、部分成功与采集失败返回可区分的结构；权限、版本冲突和非法请求沿用标准错误协议。保存结果时再次校验操作者权限，避免长请求期间禁用用户仍写入。

机器列表增加 CPU、内存、磁盘摘要和采集状态；详情区展示磁盘和网卡明细、最后成功时间及最近失败原因。管理员看到“更新机器信息”，普通用户只读。采集中禁用按钮并展示进度状态，结束后刷新详情。

## 验证与交付

先测试后实现：密码往返加密、缺密钥、错误密钥、空白密码保留、清除、所有 API/审计不泄露密码；权限/CSRF/并发/超时/输出上限；Linux 输出解析及缺项；旧数据迁移；前端表单与刷新状态。

远端连接使用可注入 transport 测试替身，必要时独立本地 SSH fixture 验证协议，不连接或改动用户真实机器。前后端定向测试、类型检查、构建后提供用户手工验收步骤。此次不重启当前网站、不修改现有数据库与 .env，不自动提交其他未提交代码。
