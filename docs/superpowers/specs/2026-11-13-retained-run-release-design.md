# 保留失败任务残留并允许隔离重跑

## 目标与范围

用户允许保留旧任务残留，不清理旧挂载，并在部署新版 DTT 后重跑引导功能测试。
不修改任务结果为成功，不将残留标记为 removed，不删除资源账本。

## 方案

采用显式、可审计的管理员确认操作。拒绝直接修改数据库释放锁；不自动在失败任务结束时解锁。
常规完整清理仍保留为原有默认流程。

## 核验与释放

- 操作仅限管理员，并要求明确确认保留残留。
- 服务端重新核验全部子任务的远端结束身份，确认环境恢复成功且没有进行中的关联清理。
- 远端状态不明、身份变化、环境恢复未完成或清理未结束时拒绝释放。
- 在事务和已有互斥锁保护下，仅释放该任务的集群、机器、运行环境占用。
- 保留资源原状态、失败结果与历史日志，记录操作者、时间、释放范围及残留摘要。

## 重跑与后续清理

- 新任务必须重新预检，使用新的任务 ID、文件系统名称及隔离目录，不复用旧残留。
- 保留残留后，旧任务的清理必须重新申请资源占用；新测试运行时不得并发清理。
- 重复确认是幂等的，不能影响其他任务已经取得的锁。
- 页面明确区分“残留已保留、占用已释放”与“清理完成”。

## 验证与发布

覆盖权限、远端核验失败、身份变化、恢复失败、清理竞争、重复操作、新任务隔离及后续清理互斥。
部署前后核验服务健康、镜像版本；从网页提交一个原失败用例，检查运行、清理和报告结果。

## 非目标

不引入强制解锁通用接口，不跳过任务身份检查，不批量删除残留，不修改磁盘挂载传播属性。
