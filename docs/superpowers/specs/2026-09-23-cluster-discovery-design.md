# 集群发现与状态展示设计

日期：2026-09-23
状态：待书面评审；用户已确认交互方向与 SSH 用户切换规则。

## 1. 目标与已确认需求

把集群录入改为“选择机器 → 指定 Linux 执行用户 → 发现集群 → 勾选导入”。不要求用户先登记上下文，也不要求填写 dingo 绝对路径。机器已配置 dingo 环境，使用目标用户登录环境的 PATH 查找工具。

一台机器有多个 Linux 用户，每个用户可有多个集群。网站登录账号、机器资源的 SSH 登录用户、执行 dingo 的 Linux 用户是三种不同身份。远程连接始终使用机器资源中的 SSH 登录用户和既有凭据；需要时再切换执行用户。

集群概览为全宽列表，每行一个集群，各列搜索排序，点击进入独立详情。详情结构化展示 `dingo cluster status -sv`，保留原始输出。机器资源、测试环境、已有配置版本继续可用。

本设计替代原平台设计中“先 checkout 再执行”的集群目标选择方案，也替代手工登记集群管理字段的主流程。独立上下文管理不恢复。

本轮包括发现、导入、查询状态、概览、详情及兼容迁移；不实现部署、升级、启停、重启、清理或测试执行。

## 2. 已知命令契约

用户给定的发现输出：

```text
main-dingofs
test-dingofs
```

`dingo cluster ls` 每个非空行一个集群名称；去除首尾空白、移除终端颜色控制序列并保序去重。设置条目数、单名称长度和整体输出上限；格式异常明确报错，不把错误文字导入为集群。名称传递始终做参数引用，不拼接未经引用的 shell 文本。

状态查询示例：

```bash
dingo_cluster=main-dingofs dingo cluster status -sv
```

在每次命令的独立进程环境中指定 `dingo_cluster`，不依赖前一次 export，不执行 checkout，不写用户默认配置。发现时清除继承的 dingo_cluster，避免平台自身或 SSH 会话环境影响查询。

状态输出包含：

- 查询提示：`Get Service Status: [OK]`。
- 集群头：cluster name、cluster kind、mds addr、tikv addr。
- 表格：Id、Role、Host、Instances、Container Id、Status、Ports、Log Dir、Data Dir、Raft Dir。

当前示例为 main-dingofs / dingofs；一个 Host（dingo126）；10 个服务：coordinator 3、store 3、mds 3、executor 1；每行实例 1/1；Status 为 Up 19 hours。没有版本字段，不展示虚构的版本信息。

实现和验收以真实原始文本为准，不把聊天粘贴产生的行尾反斜杠当成 dingo 格式，也不擅自从真实路径删除字符。

## 3. 发现与导入流程

概览右上角主按钮为“发现集群”。表单只有两个必填项：机器资源、执行用户名；用户名默认取机器资源的 SSH 用户，可以修改。

提交后顺序执行：

1. 检查机器存在、未归档、已具备连接凭据。
2. 复用机器资源的 SSH 主机密钥信任流程；未知或变更密钥进入明确确认流程，不自动信任。
3. 使用登记的 SSH 用户连接，按第 4 节进入目标用户登录环境。
4. 验证实际 uid/用户名、HOME，并运行 `command -v dingo`；找不到工具时提示具体机器与用户。
5. 执行 `dingo cluster ls`，保存有期限的发现结果。
6. 显示名称、已登记/未登记状态，支持全选、搜索、勾选导入。
7. 在事务中去重导入；导入成功后触发各集群状态采集。状态失败不回滚已导入资源。

一台机器不同用户分别发现，不枚举全部系统用户。读取集群目录不等于部署或新增远端集群。再次发现未出现的旧集群只标记“本次未发现”，不自动删除、归档或断开测试环境关联。

发现结果绑定发起网站用户、机器 ID/修订、执行用户、观测到的用户配置身份、到期时间。导入必须从有效发现结果选择，不接受客户端伪造机器和集群名称。导入期间机器归档或连接配置改变时拒绝旧结果，要求重新发现。

## 4. 用户切换和临时密码

### 4.1 正常路径

- SSH 用户等于目标用户：使用该用户的登录 shell 环境执行固定命令。
- SSH 用户不同：优先尝试 `sudo -n -i -u <目标用户> -- ...`，不等待密码；root 也走受控的用户切换方式。
- 用户名作为参数校验及引用，不允许构造任意 shell 指令。平台只提供预定义的发现、状态命令，不能提交任意命令文本。
- 加载目标用户 HOME、PATH 和登录初始化文件，再解析 dingo，不能沿用登录用户的 HOME 或 dingo 路径。明确设置本次 dingo_cluster 后运行命令，避免登录脚本覆盖选定目标。
- 执行前校验实际身份；sudo 失败不回退为 SSH 用户继续执行。

### 4.2 需要密码时

只在远端明确请求认证时创建“需要密码”状态。用户不存在、sudo 拒绝授权、缺少 sudo、登录初始化失败、dingo 不存在、SSH 认证失败分别报告，不都归类为密码缺失。

使用受控的 sudo 提示标识识别认证请求及被认证账号；默认 sudo 通常需要 SSH 登录用户密码，但不能假定所有系统如此。针对 targetpw/rootpw 等策略，提示以远端实际认证账号为准；无法可靠识别时不猜测账号。没有 sudo 的主机在本轮明确报告不支持，不自动尝试不受控的 su 会话。

弹窗显示：执行机器、SSH 登录用户、目标执行用户、需要密码的认证账号、本次动作。密码默认仅用于本次获准操作；一次批量导入后的初始状态采集可作为同一个短期操作批次，批次结束立即释放密码，不延用到其他用户、机器或后续手动刷新。

密码通过请求正文传入，在短生命周期执行进程内使用，通过 stdin 交给认证命令；不放在 argv、环境变量、数据库、队列消息、审计字段、日志、异常文本或浏览器持久存储中。处理过程关闭回显；普通命令输出中出现 Password 字样不能触发密码发送。

等待人工输入时不长期占用远端进程；保存无密码的短期挑战，关闭当前会话。提交密码后重新核验机器修订、主机信任、目标身份和挑战，再重试同一动作。挑战绑定发起者、动作、目标、到期时间，一次消费；限制重试次数，取消、过期或账号失效后不可重放。

本轮不提供“记住切换密码”。后续再次需要认证时可再次提示。网站用户密码不用于 SSH 或 sudo。

## 5. 集群身份和存储

Cluster 保留稳定 ID、名称/显示别名、真实 dingo 集群名、执行机器 ID、执行用户名和既有配置关联。内部记录最近确认的工具解析路径、目标用户 HOME/配置身份供诊断和去重，不让用户重复填写，也不作为未来命令固定工具路径。

同一管理入口以机器资源 ID、执行用户、实际配置身份、真实集群名去重；不同入口下同名集群允许并存。现有全局唯一的展示名称约束不能阻止同名集群导入，需要迁移为非唯一或独立展示别名。界面在名称旁配合机器、用户消除歧义。

不同管理入口可能指向同一实际部署，本轮不根据同名或主机集合自动合并。后续破坏性运维需要可靠实际集群标识与资源锁，本轮读取状态不依赖其完成。

增加状态快照和最近尝试元数据：

- 最近成功快照：解析后的集群头、服务列表、角色汇总、运行实例/预期实例、节点数、解析版本、原始输出、采集时间。
- 最近尝试：状态、开始/结束时间、可展示错误码、退出码、是否截断、受限原始输出。
- 操作租约/token：防止并发旧请求覆盖较新的结果；超时或进程退出后可恢复。

使用独立的发现记录和有期限的操作/认证挑战；不新建需要用户维护的上下文资源。原始输出只按文本渲染，统一做大小限制和敏感字段过滤，不解释其中的 HTML/终端控制字符。

## 6. 概览和详情

### 6.1 集群概览

全宽列表列顺序：集群名称、集群类型、dingo 执行机器、执行用户、运行状态、节点数、服务数、运行实例/预期实例、最近成功采集时间、最近采集结果。

每列可搜索和升降序排序；数字与时间按实际值排序，缺失值置后。先全量筛选排序再分页，避免只能搜索当前页。点击任意一行进入 `#/clusters/<id>`；刷新可直达详情；返回概览保留搜索、排序、页码。

未采集和采集失败的已登记集群始终可见，缺失字段留空，状态显示未知/未采集。发现导入完成后清理会隐藏新资源的旧筛选，展示导入结果入口。

### 6.2 集群详情

1. 顶部：名称、类型、执行机器、执行用户、数据时间；返回概览、刷新状态、编辑登记信息。
2. 连接信息：MDS 与 TiKV 地址，按地址列表显示并支持复制。
3. 汇总：节点数、服务数、实例统计、角色分布、异常数。
4. 服务表：服务 ID、角色、Host、Instances、Container ID、运行状态、Ports、目录入口。角色、主机、状态可筛选，异常优先，空值不臆造。
5. 目录展开：Log Dir、Data Dir、Raft Dir，支持复制；`-` 作为未提供。不会因为点击目录就访问或修改远端文件。
6. 原始输出：可展开查看输出、时间、退出码和错误。解析失败也可查看。
7. 保留既有集群 YAML 草稿/版本编辑区域；保存配置不执行远端部署。

Host 按原始输出的主机标识去重；示例中的 dingo126 算一个节点，但不声称已识别物理机。仅在与资源地址/明确别名有唯一匹配时提供机器详情链接；歧义和未登记节点显示原文。实际拓扑节点来自采集，不要求重复手选，也不从节点名称猜测 SSH 凭据。旧手工关联节点保留为登记信息，不自动删除或覆盖。

## 7. 解析和状态语义

先验证命令执行结果，再解析集群头及表格。返回的 cluster name 必须与请求一致，不一致是明确失败，不更新成功快照。

解析器清除 ANSI 控制序列、跳过已知进度/分隔行；使用表头、固定字段和列间分隔信息识别完整 Status 字段，不能简单按单空格拆分。Instances 解析为运行/预期整数；原始值保留。对于无法可靠解析的路径或行，标记解析不完整并保留原文，而不是丢弃异常行。

- 全部运行：所有服务的已知状态均为运行，且运行实例等于预期实例；只表达进程运行，不等同业务健康。
- 部分异常：可确定存在非运行实例、显式异常状态或实例数不符。
- 全部停止：服务集合非空，且所有实例均被明确观测为停止；不能由 SSH/命令失败推断。
- 未知：尚无可信快照、空服务集合或输出不能完整解释。已有明确异常可以显示异常，但未知行不能被算作运行。

`Get Service Status: [OK]` 仅表示查询提示，不是健康结论。容器 Up 后附带 unhealthy 等信息时不能判为全部正常。未知状态保留文本。部分解析失败不覆盖最近完整成功快照，最近尝试结果展示失败原因及原始输出。

## 8. 刷新、并发与权限

首次导入触发一次状态采集；进入详情先显示缓存，再触发一次刷新；概览支持刷新所选/全部已登记集群。第一版不提供无人值守定时轮询，避免反复触发密码交互。

远端只读操作有统一总超时、输出上限和机器级并发限制。默认建议：发现 60 秒、状态 120 秒、输出上限 2 MiB、每台执行机器同时最多 2 个动作，均由服务端配置。页面离开后无密码操作可以在租约内完成；取消或超时终止子进程并关闭 SSH 通道，不能宣称已经完成任何远端变更。

集群名只进入该次命令环境，不改变共享默认选择。同一集群采集请求合并或返回正在采集；不同用户查询同一集群不共享密码挑战。后完成的旧请求不能覆盖最新目标或快照。

管理员发现、导入、修改、归档登记；普通成员查看并触发固定的只读状态查询。所有动作需要登录和 CSRF 防护；审计记录发起者、机器、执行用户、集群、动作、耗时和结果，不记录凭据。未知/变更 SSH 主机密钥仍由管理员按既有流程确认。

## 9. 接口与模块边界

建议独立 cluster discovery/status 路由，注册在通用资产路由之前：

- 发起发现、查询发现进度/结果、提交临时认证、取消发现。
- 从有效发现结果批量导入；重复提交幂等返回同一批资源。
- 集群概览、集群详情、发起状态采集、查询采集结果、提交该动作临时认证。

密码字段使用秘密类型及日志过滤，不使用通用资产 PATCH 保存。客户端只传资产 ID、执行用户名、发现条目和操作 token；不能指定任意命令或覆盖服务器端 SSH 凭据。

模块划分：纯文本解析器；有界 SSH/用户切换执行器；发现/导入及状态快照服务；集群专用路由；发现弹窗与密码交互；概览/详情组件。复用已有 SSH 信任、机器凭据、权限、审计和 YAML 编辑能力。扩展执行器时必须保留机器硬件采集行为。

## 10. 既有数据兼容

保留集群 ID、环境引用、节点登记关系和 YAML 配置历史。旧 dingo_path/config_dir/credential_ref 不直接删除，迁移为兼容信息；新发现默认使用目标用户环境，不强制沿用旧工具绝对路径。

旧集群第一次刷新需要确认目标用户环境下实际发现的同名集群与旧管理配置一致。相同入口且配置一致可绑定；不同配置目录或多个旧记录产生歧义时，展示“需要确认管理入口”，保留旧数据，不静默合并或重定向。按该用户环境无法找到旧集群时报告未发现，不用另一个默认集群替代。

发现新集群不恢复旧上下文菜单。历史上下文记录仍只保留恢复用途。

## 11. 验收条件

- 同机器两个用户、每用户两个集群可独立发现导入；跨用户同名可同时展示；同入口重复导入幂等。
- 同用户无需切换；不同用户免密成功；明确密码挑战后正确认证；错误密码/取消/过期/越权/重放有清晰结果。
- 不存在的用户、无授权、找不到工具、SSH 失败不误弹密码；临时密码不出现在日志、数据库、进程参数及响应中。
- 加载目标用户 PATH/HOME；两条并发命令分别选择正确集群；目标名称不匹配时拒绝覆盖。
- 用户样本解析出 10 服务、1 Host、10/10 实例、四种角色和准确地址/路径；支持空列表、空服务、停止、多词状态、颜色控制序列、畸形/截断输出和超时。
- 已登记但未采集的集群可见；采集失败保留旧成功数据及其时间，不显示成已停止。
- 浏览器验证发现、认证、勾选导入、概览逐列过滤排序、详情刷新、目录复制、原始输出、返回状态保留和 YAML 编辑。
- 迁移保留已有资源关系；旧配置有歧义不会错误重绑；权限、机器采集和用户管理回归通过。

验证使用隔离数据库、模拟 SSH/受控回环 SSH 服务及用户提供的样本；不连接真实 DingoFS 集群，不执行集群运维命令。
