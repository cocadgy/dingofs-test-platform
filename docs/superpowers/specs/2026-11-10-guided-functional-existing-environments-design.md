# 基于已有环境的功能测试引导设计

## 目标与已选方案

用户从“开始 → 功能测试”选择工程中已有的测试环境和用例，由集成测试框架自动准备文件系统、缓存与客户端挂载，完成测试和收尾；平台提供权限检查、任务编排、进度、日志和报告。用户不必先在平台创建文件系统或挂载，也不需要重新输入已有环境的存储和目录参数。

2026-11-10 用户已选择“先接入已有测试环境，后续再增加平台创建测试环境”的方案。本文的页面字段、默认值和实现边界是待确认的具体设计；尚不代表功能已实现或部署。

### 方案比较

| 方式 | 收益与代价 | 决定 |
| --- | --- | --- |
| 选择工程已有环境 | 保留已经维护的拓扑及专用模块配置，输入少；新机器仍需先补充工程环境 | 本期采用 |
| 平台选择机器、存储并生成环境 | 适合新集群，配置更灵活；需要增加各模块的配置能力与校验 | 后续扩展 |

平台预先创建一套资源再统一跳过框架初始化，不作为备选方案：client、fault、POSIX 等模块有各自的初始化约定，不能用一个普通挂载流程替代。

## 范围与现有基础

平台仓库为 `/mnt/disk5/daigy/dingofs-test-platform`；测试源工程为 `/mnt/disk5/daigy/dingofs-testsuite-tool/dingofs-integration-test`，通过父目录的 DTT 启动。前者已有尚未提交的环境导入、用例目录、任务、草稿、日志和报告适配实现；后者已有尚未提交的精确用例清单与事件接口。它们是可继续利用的工作树代码，不是已发布版本，不能仅检查系统中有 `dtt` 就认为支持本设计。

本设计约束本次引导入口，优先于旧的 `2026-10-15-functional-test-environments-design.md` 中“在引导中创建自定义环境”的页面顺序；不删除旧稿及其现有代码，不把无关未提交修改一并提交。

本期目标覆盖 daily 的 12 个模块：fault、quota、basic_file_operation、mount_subdir、trash、dirstat、hot_upgrade、xattr、warmup、client、cache_node、mds_manage。每个模块须具有经过验证的专用环境匹配和生命周期适配后才能开放。POSIX、metadata_consistency、large_scale、large_scale_cache 和 mdtest 暂不纳入本期引导的可运行范围，展示时标明“暂未接入”，不影响命令行原有功能。性能测试仍使用单独入口。

本期不提供环境编辑、复制为新环境、用户另选已有文件系统、强制跳过初始化、二进制覆盖或无限循环运行。专用环境本身约定的固定文件系统仍按模块规则处理。程序来源、存储、客户端和缓存参数沿用所选环境，并在摘要中展示。保留原有接口的兼容性，不以新向导替换独立的机器、集群、存储、缓存组或挂载引导。

## 已有框架行为与接入要求

`--env` 指向 YAML 顶层的环境名称，不是文件名。环境解析包含 base 继承及存储配置；同一个 YAML 可以含多个环境。普通套件执行环境解析、创建带时间后缀的文件系统、按配置准备远程缓存、挂载客户端、逐用例执行以及收尾。client/fault 采用固定文件系统检查，其他专用模块也有各自的 hook。

`run_tests.py` 支持每个模块分别指定环境；当前 DTT int 包装层则给同次调用中的所有模块传同一个环境。因此平台任务采用“一个父任务、多份模块子任务”，每份子任务只传一个模块及其环境，按顺序调用 DTT，不把不同环境拼成一次共用 `--env` 的命令。

当前标准 setup/cleanup 会重新按环境名解析配置，入口临时覆盖的 MDS 或文件系统名不保证同步生效；现有标准清理还存在按文件系统名称前缀匹配多个资源的问题。这两处是上线前必须补齐的接入条件，不靠页面隐藏或命令行覆盖规避。

## 引导步骤

整体保持缓存组和挂载引导的视觉及交互习惯：清楚标明步骤，常用内容展开，高级内容收起，字段左右对齐，勾选框在名称左侧，跳转操作使用按钮。这里确定内容和行为，不引入新的视觉样式。

### 第一步 选择测试环境

必选目标集群和默认测试环境。集群选项显示“集群名称 · 管理机器名称（IP）· SSH 用户”；目标集群用于过滤环境和权限校验，不会把所选 YAML 的 MDS 地址偷偷替换成另一个集群。

环境选项显示真实环境名及主要测试机器，支持搜索；详情显示源文件、继承来源、MDS 地址、各机器名称/IP/执行用户、客户端总数、缓存节点总数、存储类型、文件系统命名规则、目录和二进制路径。没有可靠数量时显示“按用例决定”，不把 YAML 条目数当作实例总数。秘密不显示。

基础模板、缺失配置、源文件已改变、目标不一致或没有权限的环境显示具体不可用原因。只剩一个可用选项时可以预填，多个选项不擅自选中第一项。没有合适环境时提供“刷新环境列表”和“查看环境要求”，本期不引入新增环境表单。

控制机使用所选集群登记的管理机器，显示名称、IP 和 SSH 用户；它负责启动 DTT，不等于所有客户端都部署在这台机器。实际客户端、缓存和其他执行主机以环境解析结果为准。控制机不可用时阻止启动，不自动换机器改变执行位置。

### 第二步 选择模块和用例

按模块展示用例，支持名称/编号/路径搜索、模块内全选、单选和“仅看已选”。没有任何用例时不能继续。展示模块、用例编号、中文名称、级别以及专用环境要求；缺少元数据时保留原路径和缺失说明，不编造描述或运行时长。

每个已选模块各有一个环境选择框。第一步选中的环境兼容时作为默认值；不兼容时保留选择意图并要求为该模块选择合适环境，不悄悄替换、不静默跳过用例。用户可以把一个兼容环境应用到其他模块，服务端仍逐项校验。所有模块环境必须属于第一步所选集群。

兼容性同时检查模块与所选用例。已有 required_environment、compatible_environments、contract 或专用配置的约束由测试框架的同一套只读校验逻辑返回；无约束声明不能直接解释为兼容。每个适配模块需声明并检查所需能力。fault 涉及的停止服务、注入故障等影响范围在确认页单独列出，未配置必要工具、恢复规则或权限时禁止执行；不默认启用高风险故障注入。

提交的是相对 YAML 路径及 SHA256 的精确清单，不用模糊 `--case` 字符串代替勾选结果。后端校验边界、去重、可发现性、哈希及模块匹配，禁止绝对路径或路径穿越。

### 第三步 运行设置

| 项目 | 必填与默认值 | 行为 |
| --- | --- | --- |
| 任务名称 | 自动填写“功能测试 集群名 时间”，允许修改 | 不要求用户额外输入 |
| 每个模块最长运行时间 | 高级选项，默认 1440 分钟，可设 1 至 1440 分钟 | 从子任务实际启动计时，排队不计入；到期申请停止 |
| 失败重试次数 | 高级选项，默认 0，可设 0 至 5 | 使用框架已有的 FAIL 重试语义，不重试初始化失败或状态未知的任务 |
| 环境收尾规则 | 只读说明 | 普通套件成功后清理、失败默认保留现场；专用模块按其恢复与收尾规则执行 |

默认超时选择 24 小时，是考虑已有 client 等模块可能运行数小时的设计建议；它不是预计耗时。模块按框架注册顺序串行，不新增顺序拖拽。普通用例失败后，当前模块按原流程继续；模块结束后，只有确认没有待保留资源、必须恢复的状态正常且收尾完成，才可启动后续模块。

本设计采用保守的失败现场策略：只要存在待保留的文件系统、挂载、缓存或故障现场，就停止父任务的后续调度，将剩余模块和用例标为“未执行”，父任务记录失败及停止原因。初始化/清理错误、恢复失败或状态未知同样不能继续。不得为继续下一模块而自动清掉现场，也不自动恢复这份已结束的父任务；用户处理并复核后可重新选择未执行用例建立新任务。此规则是本设计提出的默认行为，不改变命令行 daily 的现有调度。

### 第四步 检查并启动

摘要按模块列出环境、用例数、目标集群、执行机器/用户、预计创建或复用的资源、故障影响及收尾规则。“检查环境”执行只读预检；通过后“开始测试”才可用。改变集群、环境、用例或相关配置都会使预检失效，服务端在启动前再次检查。

只读预检包括源配置与用例版本、权限与目标绑定、SSH 连接、DTT 运行时能力、需要的二进制/工具、目录及端口冲突、资源占用和配置格式。不得调用 env_setup，不创建文件系统、不挂载、不启停服务、不修改权限。框架 `--check` 只作为格式及处理器检查，不能代替远端连通性检查。不能凭只读检查断言实际创建一定成功。

需要安装或更新托管 DTT 时，明确展示目标机器、用户及更新内容，经用户点击确认后走已有工具包任务；不隐藏在只读预检中自动安装，不修改正在运行的版本。安装后重新预检。

预检结果给出具体机器和原因。执行故障类用例时，还需明确确认将影响的集群和服务。点击启动后返回任务 ID，重复点击或网络重试只能得到同一个父任务，不得重复启动。

## 草稿与导航

从“开始”新建时生成新的引导实例，不自动跳到上次已完成任务。未提交草稿可以提示恢复或新建，只有用户主动选择恢复才回到该草稿。已提交任务通过任务记录查看，不作为新向导的恢复结果。

草稿绑定用户，保存字段、步骤及乐观版本，不保存密码。草稿格式带版本；旧的六步自建环境草稿保留但不能当作新的已有环境向导恢复。跨标签页修改产生冲突时提示，不覆盖较新版本。

填写中点击左侧菜单、返回或其他内部页面，先确认离开；保存草稿不等于允许静默离开。刷新或关闭页面采用现有未保存提醒。恢复后重新校验环境、用例及权限，不复用过期预检结果。启动后离开结果页面不终止远端任务。

## 执行配置与资源隔离

### 单一任务配置

每个模块启动前，从已冻结版本的原环境解析一次有效配置，建立供 setup、executor、hook 和 cleanup 共用的任务上下文。保留原环境名称，保证 required_environment 等专用约束仍成立；不把预置环境改名成普通自建环境，也不覆盖其集群、主机、存储或固定文件系统语义。

普通模块自动创建资源时，在允许动态命名的位置加入子任务唯一标识，并记录实际产生的资源；文件系统、缓存组、端口及挂载路径必须在这份上下文中贯穿初始化和用例内重新挂载。专用模块要求固定资源名称时，不强行改名，由专用适配器声明既有资源及可修改范围，并使用互斥限制。

资源台账按子任务记录资源类型、实际名称/ID、集群、机器、执行用户、路径、端口、创建时间、是否本次创建和清理状态。清理只针对有明确归属且仍匹配的本次资源，不能按宽泛前缀删除其他任务的文件系统；既有固定资源不得作为本次创建资源整体删除。setup 部分失败也必须留下已创建资源记录，失败保留现场时可在结果中定位。故障恢复不是可任意跳过的清理操作。

首次实现不提供新的“一键清理失败现场”或强制停止接口；已有资源管理可供有权限用户处理，不能在未知归属时自动执行破坏性清理。

### 锁与排队

父任务串行运行其模块；运行前以集群及会被修改的目标机器集合申请持久化占用记录。不同环境名不是隔离依据。平台内共享这些资源的功能测试排队，不能因调度线程或 API 并发同时启动。父任务执行期间持续持有占用，普通用例失败不释放给另一任务插入执行。

与已知性能测试、工具部署以及资源管理写操作的冲突在统一服务端检查，读操作可继续。控制机仅承担调度时不等同于独占其所有集群，但其托管运行时不能在任务执行期间被替换。无法精确判断冲突时按目标集群/机器保守拦截并说明原因，不自行停止其他任务。

占用记录只有在远端执行结束且必须恢复的状态已确认后才能释放；心跳超时、平台重启或 SSH 断连不能证明任务停止。需人工处理的残留资源持续占用其实际冲突键，直到复核；不确定状态不自动重跑。对已确认结束的任务，允许有权限用户通过已有资源管理处理台账中对应的残留资源，不将这些清理操作误拦截为另一测试任务；仍需操作确认并核实精确目标。处理后只读复核已停止/卸载/删除及恢复状态，记录审计后才释放对应占用，不通过未经复核的“标记完成”释放。排队任务启动时重新验证权限和版本，不假定提交时的检查永久有效。

平台锁不能约束外部 Jenkins、命令行 DTT 或手动操作，确认页明确提示避免这些任务共用同一环境；不承诺对平台外执行提供全局互斥。

### 版本和秘密

任务冻结原环境名、环境版本、继承链与存储来源摘要、用例路径及哈希、框架源码版本/内容摘要、DTT 运行时版本、目标机器身份、模块分配及运行选项。记录实际二进制路径和可获取的版本/commit；获取不到时明确未知，不用框架 Git commit 冒充 DingoFS commit。

预置 YAML 留在受控源目录或匹配的运行时包中，数据库和前端仅保存脱敏摘要及版本引用。目标机配置及依赖文件必须与冻结摘要一致，不一致则在创建资源前停止。继承链变化也算源变化，不只比较叶子 YAML。运行过程中所需源包必须固定，不能随部署切换到新内容。

控制机使用平台登记的 SSH 密码认证。环境内部执行所用主机及用户必须完整列出并映射到用户有管理权限的机器，覆盖 MDS 命令机、客户端、缓存、故障目标及用例引入的额外目标；无法确认的目标不得运行。沿用预置环境自身认证配置，不把控制机身份自动替换到所有远端机器；不支持的认证方式或身份映射在预检中明确拒绝。

源配置中的密码、密钥等不得进入任务快照、URL、命令参数展示、日志或可下载报告。执行时收集需要脱敏的秘密并沿用加密凭据管理；任何必要的临时秘密文件权限为 0600，只供任务使用，结束后清理。不能只脱敏平台登录控制机的密码而漏掉预置环境及存储凭据。

## 任务状态与结果

父任务记录用户请求及模块顺序；子任务记录模块、环境、精确用例清单、开始/结束时间、阶段、状态、结果、资源台账、日志和报告路径。子任务阶段为预检、准备环境、执行用例、收尾、生成报告，逐阶段记录时间；准备阶段也显示实际执行机器名称、IP 和用户，不只显示一个不断转动的“执行中”。

结果页汇总模块用例数、最终通过/失败/跳过/未执行数、套件错误、耗时、清理/恢复情况和报告状态。用例重试保留所有 attempt，但最终统计按该用例最后一次结果，不重复增加用例总数。尚未运行的模块和用例标为未执行，不计通过。用例通过但初始化、恢复或清理失败不能显示任务成功。

事件采用结构化 JSONL，包含父/子任务标识、模块、阶段、用例相对路径、attempt、执行机器/用户和状态。事件序号或唯一 ID 支持去重；断线恢复后按游标读取，不能因日志截断或最后若干事件窗口漏掉早期用例。进度依据真实事件，不制造百分比；全部用例结束但清理尚未完成仍不能显示整体完成。

“停止测试”先进入“正在停止”，通知当前子任务在安全边界结束并执行必须恢复的 hook，不启动后续模块。超时使用同样机制，并保留“超时”原因，不能伪装成手动取消。停止请求十分钟后仍无法确认结束，标为“需要处理”，继续采集状态且保留占用，不自动 kill 所有客户端/缓存或强行卸载。正常观察到退出及收尾完成后才标为已取消/超时结束。

退出码 0 不代表所有勾选用例已执行：成功必须同时满足预期用例清单完整、无失败/套件错误、必须恢复和清理均成功、无取消/超时、远端结束可确认。测试结果与报告生成状态分别记录；报告失败不能覆盖已经采集的用例结果，也不能提供一个指向旧报告的成功链接。

每个子任务使用独立输出目录和报告路径，父任务提供模块汇总及各模块 Allure 按钮。本期不合并不同模块的 Allure HTML，不指向全局 latest，也不复用固定 HTTP 端口判断报告归属。报告通过带任务权限的现有代理访问，报告缺失时显示具体原因。运行日志同样隔离并脱敏。

任务记录支持查看日志、Allure、重新运行全部和仅重跑失败用例。重跑创建新父任务并记录来源，重新检查权限、占用和源版本；不能自动复用未知状态或失败现场中的挂载。原版本无法安全重建时返回配置页展示差异，由用户重新确认。仅重跑失败不包含未执行或初始化错误；没有可重跑的失败用例时禁用并解释。

## 接口及迁移边界

继续复用 functional 目录、环境导入、草稿及远端 supervisor 的已有抽象。扩展已有任务模型为父请求及模块子任务，新增持久占用与资源归属信息，不再让一个全局 env_name 代表所有模块。旧的单环境调用在服务端规范化为同环境的模块计划，已有历史记录仍可读取。

新增或扩展只读环境兼容性和预检接口，任务提交接受模块到环境 ID/版本的映射、精确用例清单和幂等请求 ID。机器、环境、任务、报告和草稿的权限在后端检查；危险操作遵循现有确认、CSRF 和审计机制。环境同步以源文件和顶层环境键识别条目，重复键、继承循环、缺少 base、来源消失均给出明确状态。

接入 `#/start/functional` 并与现有 functional 任务列表/详情共用任务接口。先做源码与迁移清点，避免把现有未跟踪迁移视作已上线或重复创建表。部署运行时按不可变版本保存，平台必须确认精确用例、共用任务上下文、资源归属清理、阶段事件和取消接口均可用；旧运行时缺能力时阻止启动并提示更新，不降级为运行整个模块。

## 验收与发布条件

实现后的验证以替身 SSH 和测试框架单元测试为主，以下行为均需覆盖：

1. 预置环境按框架规则解析继承与存储，模板和不匹配环境不能提交，全部目标机器校验权限。
2. 一个模块一个环境、多模块分别选环境都生成正确子任务；不兼容项不静默跳过或换环境。
3. 准备环境使用确认过的配置；普通动态资源有独立身份，专用固定资源按原约定执行；清理不碰其他任务或既有资源。
4. 只读预检不创建资源；缺工具需显式安装确认；源或用例变化使预检失效。
5. 并发提交、跨标签页重复点击、工作线程重启不重复启动；共享资源互斥，状态未知不释放占用。
6. 准备失败、用例失败、恢复失败、清理失败、报告失败可区分；事件完整性、重试计数、取消和超时不会产生假成功。
7. 新向导不自动跳到旧任务；草稿恢复、离开提醒、列表刷新和机器/IP/用户展示符合现有引导习惯。
8. 各模块报告属于本次子任务，不引用昨天或其他并发任务的 latest；所有 API、日志、报告不泄露秘密。

真实网页验收先在明确授权且无冲突的 126 测试环境运行一个最小普通功能用例，确认创建、挂载、执行、清理和报告完整链路；再分别验证固定文件系统模块和专用环境适配。故障注入、服务停止、大规模或长时间工作负载不能夹带在普通冒烟验收中，须单独确定范围。当前设计阶段不运行这些测试。

设计通过后再编写实施计划。实现提交只包含核对过的功能相关改动，迁移、运行时和平台配套发布；历史任务需要的运行时版本不得随升级删除。发布后回读入口、运行时能力与报告路由，不能仅以构建成功宣称已可用。

## 留给实施者的选择

可自行决定组件拆分、分页大小、轮询间隔、数据库索引和版本化迁移编号，沿用现有技术栈与 UI 样式。不能自行扩大首期模块范围、增加自建环境或二进制覆盖、改变失败保留规则、静默切换目标机器或放宽清理归属限制。
