# 功能测试环境配置

## 目标与边界

用户在“配置管理 → 测试环境配置”查看现有测试环境，并为没有预置 YAML 的机器创建可复用的功能测试环境。测试任务选择一个环境，再选择用例；平台从所选集群读取 MDS 地址，从机器资源取得 SSH 连接信息，从存储配置取得 S3/RADOS 连接参数。保存环境本身不创建文件系统、不挂载客户端，也不启动缓存进程。只有启动测试任务后，测试框架按环境配置执行其原有 setup/cleanup。

首次上线导入 `dingofs-integration-test/conf/env/*.yaml` 的所有顶层环境名：当前来源为 41 个文件、83 个条目，其中包括可被其他条目继承的 base。导入条目保留“预置”来源、源文件、内容摘要与继承关系；列表区分“可直接运行”和“基础模板/需补全”。预置环境直接沿用镜像中的原始 YAML 执行，不复制或展示其中的密码、令牌和存储密钥。要用于新机器时，用户通过“复制为自定义环境”显式选择新集群、机器和存储配置；不能把旧环境中固定的主机、路径或凭据暗中带到新机器。

第一版自定义环境支持单客户端的常规功能测试；默认测试机是集群管理机器，用户可改选自己有权限的机器。缓存组、故障注入和大规模测试等特殊模块继续要求其专用配置，界面根据用例模块显示缺少的能力，不将一个普通环境宣称为适用所有用例。现有预置环境及直接输入环境名的 dtt 命令保持兼容。

## 页面与用户流程

“测试环境配置”作为配置管理的独立页签。列表展示名称、类型（预置/自建）、关联集群、测试机、存储类型、客户端数量、适用模块、验证状态、更新时间；可搜索、查看详情。预置环境可以查看脱敏的有效配置、复制为自定义环境；自建环境可新增、编辑、停用、复制、删除，已被任务引用的环境保留历史快照。普通用户可查看全部环境，只能管理自己创建的环境以及自己有管理权限的目标机器与集群；管理员可管理全部。

新建向导先选集群，再选测试机和已启用的存储配置；填写挂载根目录、文件系统名前缀、客户端数量，按需选择缓存组、客户端二进制或高级参数。MDS 地址从集群最近成功状态填入并显示采集时间。没有可用存储配置时提供跳转入口。保存前显示不含密钥的配置预览、预计将创建的资源和验证结果。基础验证包括集群/机器权限、SSH 可达、目标机 dtt 与 dingo 可执行、挂载路径合法且不与已登记运行任务冲突、存储配置启用及版本有效；验证失败指出具体字段或机器。验证和保存均不运行测试工作负载。

功能测试创建页将现有单一的环境下拉框改为测试环境配置选择：按集群过滤预置与自建环境；预置环境通过有效配置中的 MDS 地址与所选集群最近成功快照比较，并通过客户端主机名/IP 与已登记机器标识比较；任一绑定目标不一致或无法可靠判断时标记不适用，不能直接提交。选择自建环境时显示摘要和最近验证状态。用户仍可选择模块/用例、重试和超时。任务记录环境 ID、版本、非敏感配置摘要、用例目录摘要；编辑环境不改变已排队或运行中的任务。重跑使用原任务的环境快照；环境版本或源文件已变且无法安全重建时要求重新确认，不悄悄改目标。

## 数据与预置导入

新增 `functional_environment_profiles`，不复用旧 `inventory.environments`：后者是早期资源关系模型，不能表示未绑定集群的预置条目及测试框架配置。记录拥有者、来源、名称、启用状态、关联集群/测试机/存储配置、结构化非敏感配置、密文、版本、预置源文件/环境键/摘要、验证状态及时间。预置记录以“源文件相对路径 + 顶层环境键”为稳定身份；同步操作幂等，新增条目自动出现，源摘要变化时更新展示元数据并标记需验证，已创建的任务快照不变。源文件消失时标记不可新用，不删除历史。

导入器使用 YAML 解析器读取文件，并遵循测试框架的 `base` 继承规则；捕获重复名称、继承循环和缺失 base 为明确错误。预置条目的原始 YAML 留在只读代码目录，不把明文秘密写入平台数据库或返回 API。自建环境仅引用存储配置 ID 和版本；存储凭据继续由现有加密存储管理，不在环境记录或审计事件中重复保存。选择预置环境时，执行前比较平台记录的源摘要与目标 dtt 镜像中的配置，版本不一致则停止并提示更新工具包或重新同步。

## 执行机制

自建环境在任务创建时冻结结构化配置与所引用资源版本。工作线程在执行前重新核实集群、机器、存储配置状态，再按既有的“单任务远端 supervisor”机制，在目标机器的任务专属目录生成随机文件名的环境 YAML，文件权限 0600。生成内容使用测试框架现有解析格式，包含从存储配置临时解密取得的连接信息；控制器数据库仅保存密文引用和非敏感快照。dtt 增加精确的环境文件参数，将该文件只读挂载到容器内的 `conf/env/`，以该环境键调用 `run_tests.py`。不修改仓库预置 YAML，不共享生成文件，不通过 shell 拼接配置字段。测试结束后清除临时明文 YAML；若清理失败，任务状态和诊断中显式记录路径，便于管理员处理。日志与可下载报告屏蔽凭据字段和命令中的密钥参数。

远端任务仍采用已有任务 ID、状态文件、事件流、取消标记和 Allure 报告代理。新建环境的预检与实际运行均验证目标机 dtt 运行时支持“环境文件只读挂载”；老版本不能静默退化为其他预置环境。用例清单的精确路径和 SHA256 校验保持不变。取消、超时和未知远端结果沿用当前安全策略，不重复启动不确定结果的任务。

## 接口、故障与验证

API 增加环境列表/详情/创建/更新/停用/复制/预检/同步预置接口。所有写操作校验权限、CSRF 与乐观版本，记录审计；秘密只在远端执行准备阶段解密。预检返回每项结果及可操作原因，不直接写远端测试目录。创建任务时检查环境与集群/模块兼容，任务接受 `environment_profile_id` 与 `environment_profile_revision`；旧 `env_name` 路径作为兼容分支保留，页面默认走配置引用。

测试分层验证：YAML 导入数量、继承与源变化；预置秘密不出现在 API/数据库；新环境表单和权限；配置快照与版本冲突；远端 YAML 生成和只读挂载命令；缺工具、错误存储配置、SSH 失败、取消及报告读取。先用伪 SSH/伪 dtt 做端到端本地闭环，再在受控新机器上运行一个最小文件读写用例，确认真实创建文件系统、挂载、读写、Allure 报告及清理。该真实运行作为交付验证，不在自动测试中触发。

发布时迁移数据库，运行预置环境同步，构建并部署 api/web；目标机器的托管 dtt 需要更新到支持环境文件参数的版本。上线后核对预置环境条目数与源目录一致，且现有预置环境任务仍可运行。
