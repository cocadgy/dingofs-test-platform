# 引导式添加集群设计

## 目标

在“开始”中提供“添加集群”：登记远端已有的 DingoFS 集群，不创建远端集群。流程尽量少填：先选已登记的执行机器（可先添加机器）和执行用户，再查询、选择并导入已有集群。

## 方案

复用现有 `DiscoverClusters` 的发现、认证、导入和冲突绑定逻辑，避免引导入口与集群管理入口行为分叉。引导页负责步骤入口、机器登记跳转和成功后的继续操作。若没有执行机器，点击“先添加机器”使用现有密码 SSH 机器表单；成功后返回集群引导，刷新机器列表并自动选择新机器。失败留在表单；返回不创建集群。

普通用户只填写“执行机器”“执行用户”（默认为机器的 SSH 用户）并勾选查询结果。`dingo` 路径和配置目录由发现流程取得。需要用户切换认证或已有集群入口冲突时，沿用现有明确的认证/绑定确认，不自动覆盖。离开流程时沿用已部署的左侧导航确认。

## 非目标

不新建远端集群，不增加第二套发现 API，不改变原有集群管理页面。其他未开放的引导任务继续显示“即将支持”。
