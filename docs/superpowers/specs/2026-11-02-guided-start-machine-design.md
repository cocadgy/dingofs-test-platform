# 引导式开始页与添加机器设计

## 目标

为第一次使用 DingoFS 测试平台的用户提供统一的“开始”入口。用户无需先理解机器、集群、文件系统、缓存组和测试模块之间的关系，只需选择想完成的任务，平台就进入对应的引导流程。

本期实现“添加机器”流程，后续在同一入口逐步接入添加集群、创建文件系统、创建缓存组、挂载文件系统、功能测试和性能测试。

## 用户与成功标准

目标用户是第一次进入平台、不了解左侧各资源页面先后关系的普通成员或管理员。

成功标准：用户可以从“开始”进入，在一个表单中提供最少的 SSH 信息；平台先验证连接，验证成功后才保存机器并采集硬件信息；完成页明确引导用户继续添加集群。

## 非目标

- 本期不实现其余六种引导任务的具体表单。
- 不支持 SSH 私钥、SSH Agent 或凭据引用认证。
- 不替换现有“机器”管理页；高级编辑、归档和维护状态仍在原页面完成。
- 不改变现有机器资源的所有权和权限模型。
- 不自动创建集群、文件系统、缓存组或挂载。

## 方案比较

### 方案一：先验证 SSH，成功后保存（采用）

用户提交表单后，平台验证地址、端口、用户名和密码，并执行安全的只读采集。只有验证成功才创建机器记录。失败时保留表单内容，不留下不可用机器记录。

优点是新用户看到的机器列表保持可用、干净，错误可以在当前页面直接修正。代价是需要一个专用的引导创建接口，不能直接照搬现有“先保存、再异步采集”的创建流程。

### 方案二：先保存，再异步连接

直接复用现有机器创建接口，连接失败的机器也会保留。实现较少，但新用户必须离开引导页进入机器管理页修复，不符合降低使用门槛的目标，因此不采用。

## 导航与开始页

左侧主菜单新增“开始”，放在主要业务菜单之前。登录后保持当前默认落点，不强制所有老用户进入开始页；新用户可以主动点击“开始”。

开始页显示标题“你想做什么？”和一个任务下拉框：

1. 添加机器
2. 添加集群
3. 创建文件系统
4. 创建缓存组
5. 挂载文件系统
6. 功能测试
7. 性能测试

第一项默认选中。点击“下一步”进入所选引导流程。尚未实现的流程可以显示“即将支持”和前往现有功能页的入口，但不能出现可提交的空表单或静默无响应。

开始页和引导步骤使用独立 Hash 路由，刷新页面后仍停留在当前任务；认证失效时沿用现有登录处理。

## 添加机器页面

页面只展示建立可用 SSH 连接所需的五个字段：

| 字段 | 必填 | 规则 | 默认值 |
|---|---|---|---|
| 机器名称 | 是 | 去除首尾空格；1–120 字符；名称不可重复 | 无 |
| IP 地址或主机名 | 是 | 使用现有主机地址规范化；地址和 SSH 端口组合不可重复 | 无 |
| SSH 端口 | 是 | 整数 1–65535 | 22 |
| SSH 用户 | 是 | 1–80 字符；仅字母、数字、下划线、点和横线 | 无 |
| SSH 密码 | 是 | 1–4096 字符；不去除密码首尾空格 | 无 |

密码框默认隐藏，允许临时显示；页面离开、提交成功或登录失效时清除内存中的密码。

主机别名、物理机标识、标签、凭据引用和维护状态不出现在第一版引导表单中。创建时使用现有模型默认值；用户可在机器管理页继续编辑。

页面底部显示“上一步”和“检查连接并添加”。提交期间禁用表单及重复提交，并依次展示：

- 正在连接地址和端口；
- 正在验证 SSH；
- 正在采集机器信息；
- 正在保存机器。

## 服务端流程

新增一个面向引导页的原子业务接口，复用现有 `MachineInput` 字段校验、权限检查、SSH transport、硬件采集、凭据加密、主机身份同步及审计能力。接口不得通过调用自身 HTTP API拼接现有接口。

处理顺序：

1. 校验登录用户具备创建机器的现有权限。
2. 校验字段格式，并在事务外读取名称、规范化地址和端口是否冲突；该检查只用于快速反馈。
3. 使用提交的密码执行有总超时的 SSH 验证和只读硬件采集；沿用平台当前策略，首次连接自动信任 SSH 主机密钥，不增加指纹确认步骤。
4. SSH 或采集失败时返回分类错误，不保存机器、密码、硬件快照或审计中的敏感输入。
5. 验证成功后开启数据库事务，再次加锁检查名称及地址端口冲突，防止并发重复创建。
6. 加密保存 SSH 密码，创建机器、主机标识和采集快照，写入脱敏审计记录，然后提交事务。
7. 返回机器公开信息和硬件摘要，不返回密码、密文、原始远端错误或完整原始采集输出。

SSH 验证与保存之间机器状态可能变化。接口只承诺本次验证成功，不宣称连接永久有效；后续仍允许在机器详情页重新采集。

硬件采集沿用现有 `success`、`partial` 和 `failed` 语义：CPU、内存、磁盘、文件系统或网卡中至少一类可解析时允许创建机器，缺失项在成功页显示“未知”；全部不可用时不创建机器。SSH 登录成功但采集结果为 `partial` 时，成功页明确提示信息不完整，并提供进入机器详情重新采集的入口。

## 错误处理

页面按以下分类展示可操作错误：

- 名称已存在：提示更换名称。
- 地址和端口已登记：提供打开已有机器详情的入口，但不自动覆盖。
- 地址解析失败或端口不可达：提示检查地址、网络和端口。
- 连接超时：提示目标机器或网络未响应。
- SSH 认证失败：只显示“SSH 用户名或密码错误”。
- 远端只读采集失败：说明未创建机器，并显示经过白名单映射的原因。
- 并发冲突：提示已有其他用户创建相同机器，提供打开已有记录入口。

所有失败都保留除密码外的非敏感表单内容。认证失败后密码框保留在当前页面内便于修正，但不写入浏览器存储；刷新或离开页面即清除。

## 成功页面

成功页显示：

- 机器名称；
- `SSH用户@地址:端口`；
- CPU 核数；
- 内存容量；
- 磁盘数量；
- RDMA 是否可用；
- 采集完成时间。

提供“返回开始页”和“继续添加集群”两个按钮。“继续添加集群”进入后续独立的添加集群引导，并携带刚创建的机器 ID 作为预选项。本期尚未实现添加集群引导，因此按钮显示为“继续添加集群（即将支持）”且不可提交，不跳转到现有集群管理或发现页面，避免形成错误预期。

## 安全与审计

- 仅支持 SSH 密码认证。
- 密码使用现有平台加密密钥加密保存。
- 密码不得进入 URL、浏览器存储、API 响应、应用日志、审计载荷、异常详情或远端命令。
- 服务端对 SSH 库异常做白名单错误映射，不直接返回可能包含地址或认证细节的原始文本。
- 创建成功的审计记录只包含机器公开字段；失败验证不记录密码或整个请求体。
- 沿用现有请求大小和 SSH 连接总超时。本期按产品决定不新增 SSH 探测的全局并发或频率限制；接口仍仅对已登录且具备机器创建权限的用户开放。

## 权限与兼容性

沿用现有规则：普通成员可以创建并管理自己登记的机器，管理员可以管理全部机器。开始页根据当前用户权限显示可执行项；后续仅管理员可执行的引导任务要明确标识，而不是提交后才返回 403。

现有 `/machines` 页面、机器创建接口和异步采集流程保持兼容。引导接口是面向新用户的额外入口，不改变现有自动化调用。

## 验收范围

- 左侧显示“开始”，点击进入任务选择页。
- 选择“添加机器”并进入五字段表单。
- 缺字段、非法端口、非法用户名和重复资源在提交前或服务端明确提示。
- SSH 失败时数据库没有新增机器，响应和日志不含密码。
- SSH 成功时只创建一条机器记录，保存加密密码及硬件摘要。
- 双请求并发创建相同机器时最多成功一个。
- 成功页展示硬件摘要，可返回开始页或继续添加集群。
- 原机器管理页和 API 行为不回归。
