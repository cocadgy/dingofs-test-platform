# 共享存储配置

## 目标与交互

为重复创建文件系统提供统一的 S3/RADOS 配置，侧栏新增“存储配置”。页面支持列表、创建、编辑、启用/停用和删除。配置名称可读，列表显示类型、连接位置、状态和更新时间。所有登录用户可以查看公开连接信息并选择配置；创建者可以修改自己的配置，管理员可修改全部。

S3 配置包含 Endpoint、Bucket、AK、SK；RADOS 包含 Monitor、Pool、用户名、Key、集群名。凭据复用现有加密密钥保存，普通读取接口不返回原文；编辑时密钥留空保留原值。此前 fs.get 的 AK/SK 展示策略保持原样。

创建文件系统只输入文件系统名称、分区方式并选择启用的存储配置，展示选定配置的公开连接信息。无可用配置时指向存储管理，禁止提交。配置版本变化或已停用时，要求重新选择并核对。

## 后端与一致性

新增 storage_profiles 模型及迁移，API 提供列表、新增、带 revision 的更新、删除。删除只移除平台配置，不删除真实存储和既有文件系统。配置类型创建后固定。删除采用归档，历史保留来源标识。

fs.create 接收 storage_profile_id、storage_profile_revision；后端在原有权限和操作确认校验中解析配置并验证启用状态和版本。禁止将配置引用与手动连接参数混合。原有手动参数 API 兼容。幂等请求先查历史操作，再解析当前配置。

提交时保存公开参数及凭据密文快照，工作线程使用快照；之后编辑、停用或删除配置均不改变已提交的任务。创建权限仍以目标集群管理权限为准。凭据原文不进入操作参数、步骤 JSON 或审计日志。

## 验证与发布

前端覆盖选择提交、共享配置、无可用配置、版本变化、CRUD、权限控制和空密钥保留。后端覆盖加密落库、权限、revision 冲突、停用/归档阻止新建、快照独立性与幂等。使用隔离数据库和模拟远端执行，不创建真实文件系统。

发布需要构建 api/web/migrate，执行数据库迁移，再重启 api/web。
