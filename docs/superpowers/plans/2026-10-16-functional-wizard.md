# 功能测试向导与草稿实施计划

目标：用户从集群和机器开始，按六步完成配置、保存草稿、恢复并启动功能测试。

1. 后端草稿：新增归属用户的版本化草稿表与增删改查 API，限定配置字段、拒绝密码和令牌，冲突返回 409。测试创建、更新冲突、权限和提交后的状态。
2. 执行契约：在任务提交中接受本次向导配置并冻结执行快照，验证集群、机器、存储和成员权限；沿用现有自定义环境渲染和执行器。测试选定机器确实用于调度和二进制配置。
3. 文件系统模式：自动创建时生成唯一名称；使用已有文件系统时跳过创建并保留它。为执行器添加受限参数和测试，避免影响旧任务。
4. 前端向导：六步分别处理集群、机器及 dtt 检查、二进制和目录、客户端与缓存参数、文件系统、用例与提交；上一步和下一步保留输入，错误在本步展示。
5. 草稿交互：自动保存与“保存并退出”、首页草稿列表、恢复、版本冲突、未保存提醒，启动成功后标记提交。测试保存响应不能覆盖较新输入。
6. 验证部署：后端定向测试、前端定向测试、构建、Docker 部署和真实页面只读检查。保留已有未提交改动。
