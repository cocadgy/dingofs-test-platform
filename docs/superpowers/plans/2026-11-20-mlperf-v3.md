# MLPerf Storage 3.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade DTT and the guided performance flow to support training, checkpointing and KV cache using a pinned MLPerf Storage 3.0 release.

**Architecture:** DTT owns native commands and produces a versioned normalized report. Platform validates scenario-specific requests, invokes DTT, verifies returned identity and renders metrics. Preserve legacy training requests and reports.

**Tech Stack:** Docker, Bash, Python, Pydantic, React/TypeScript, pytest, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-20-mlperf-v3-design.md`

## Global Constraints

- Three scenarios: training, checkpointing, kvcache; preserve existing training model intent.
- Pin a verified 3.0.x tag and commit plus matching DLIO requirements; do not assume current main matches the release.
- Internal comparison results are not official MLPerf submissions.
- No real workload on 129; no automatic production deployment or push.
- Work in existing isolated worktrees; preserve unrelated submodule and generated-file changes.

## Review Focus

- Legacy reports and omitted scenario fields retain training behavior.
- Unsupported models/options fail rather than silently changing workload.
- Read-only checkpoint runs need compatible existing data or an explicit preparation phase.
- Zero exit with incomplete/wrong-scenario/nonfinite results must not be successful.
- Cancellation, insufficient capacity, and old DTT capabilities produce actionable failures.
