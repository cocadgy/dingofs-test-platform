# 集群发现与状态验收

本轮将手工登记集群改为“选择机器和执行用户 → 发现 → 勾选导入”。不再填写 dingo 工具路径，不恢复上下文入口。

- 使用机器 SSH 用户连接，不同目标用户先免密 sudo；确需认证时显示认证账号并临时收取密码。密码不保存。
- 多用户同名集群可分别导入；重复导入幂等；已有集群通过显式绑定保留 ID、环境、节点登记和 YAML 配置历史。
- 全宽概览支持全部列搜索排序、分页和刷新；无快照的集群仍显示。详情支持角色/主机/状态筛选、地址和目录复制、原始输出、只读 topology.yaml。
- 主机密钥由机器创建者或管理员核验；普通成员可在自己的机器上发现、导入集群，并操作自己创建的资源。所有成员可查看已采集信息。
- 发现和状态采集使用固定只读命令。集群管理支持 start/stop/restart：服务使用 --id，角色使用 --role，全部服务不加范围参数，统一加 --force。执行前由前端确认集群、动作和目标。
- 输出不完整、目标名称不匹配、命令失败、超时，不覆盖最近成功快照。

验证使用隔离 PostgreSQL、模拟 dingo 输出与本机回环 SSH 服务；浏览器覆盖密码切换、同名导入、详情、筛选返回、原配置编辑及机器/用户流程。未连接真实 DingoFS 环境。

更新前保留正常数据库备份，再使用现有 docker compose up -d --build；迁移服务自动升级表结构。旧数据不会被自动删除。

本轮自动验证：Python 3.12 后端 107 项通过，前端单元测试 26 项通过，浏览器流程 7 项通过；前端生产构建、数据库升级兼容测试和迁移一致性检查通过。


集群管理仅允许创建者或 admin 操作，普通只读用户按钮不可用，接口同样拒绝。目标来自当前集群状态快照，服务 ID 与角色均在后端校验。按原机器与执行用户连接，逐次设置 dingo_cluster；需要 sudo 密码时沿用临时认证。

同一集群启停互斥；命令超时不自动重试。默认控制命令超时 300 秒，可用 PLATFORM_CLUSTER_CONTROL_TIMEOUT 调整（最长 1800 秒）。命令结束后前端发起状态刷新；退出码 0 表示命令完成，运行状态仍以采集结果为准。超时、失败或取消时远端可能已部分执行，取消不能撤销启停，须核实状态后决定下一步。
