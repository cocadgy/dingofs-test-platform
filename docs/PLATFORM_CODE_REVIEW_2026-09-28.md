# 平台代码审查与重构（2026-09-28）

审查对象是当前工作区，包含尚未提交的集群、资源、日志和终端功能。使用临时工作副本、独立 PostgreSQL 测试数据库与模拟远端，不操作实际 DingoFS 集群。

## 本轮发现和处理

| 优先级 | 问题 | 处理 |
| --- | --- | --- |
| P1 | 排队超时的集群控制任务仍可续租并执行停止/重启 | worker 执行前检查过期状态，保留合法密码认证恢复路径 |
| P1 | 日志读取/下载完成结果只有保留期限，没有累计缓存上限 | 已完成结果按每 API 进程最多 64 份、总计 256 MiB 回收；正在执行的任务、WebSocket 输出和 HTTP 下载期间保护结果 |
| P2 | 下载结果 API 与进程缓存的过期起点不一致 | 完成时同步保留期限 |
| P1 | 重绑集群入口后，旧缓存组/挂载记录可能跟随同一集群 ID 发往不同 MDS | 存在关联资源时禁止更换目标身份，新目标单独登记 |
| P2 | 后台刷新覆盖正在编辑的集群别名 | 区分已保存数据和编辑草稿，仅在进入编辑时初始化 |
| P2 | 较早的资源查询可能在认证完成后返回，恢复旧挑战和旧任务状态 | 请求序号与操作版本联合校验，丢弃过时响应 |
| 维护性 | 资源页面同时负责导航、表单、请求、结果与历史 | 拆分组合页、任务表单、导航、历史、状态 hook 和功能元数据 |

主要代码位置：

- `backend/src/dingofs_platform/clusters/operations.py`：任务期限校验。
- `backend/src/dingofs_platform/clusters/service.py`：资源与集群管理入口的绑定保护。
- `backend/src/dingofs_platform/remote/manager.py`、`routes.py`：完成结果回收、下载生命周期。
- `frontend/src/features/resources/`：页面职责拆分和异步响应排序。
- `frontend/src/features/clusters/ClusterDetail.tsx`：编辑草稿保留。

## 保留的设计边界

- `resources/remote_helper.py` 作为独立源码发送到远端。不能仅按文件长度拆成普通包导入；后续应先设计源码打包边界，再按进程、挂载、缓存和日志拆分。
- 不强行合并集群操作、资源操作和终端/日志会话状态机：它们的认证恢复、结果回收和连接语义不同。
- 保留用户确认的自动信任 SSH 主机、自动硬件采集、资源所有权和操作确认规则。

## 后续建议

1. **统一离开页面保护**：App hash 导航和各页 dirty 检查分散。个人资料的浏览器前进/后退、资源页外部导航尚未形成统一草稿保护。宜通过统一导航控制和浏览器测试处理，避免各页面重复确认。
2. **更新旧测试契约**：改动前，后端全量基线为 278 passed、20 failed、2 teardown errors。主要是旧测试仍期望手动指纹确认，或创建机器后假设 revision 恒为 1；自动采集会更新 revision。部分本地 SSH 测试也被创建阶段自动采集干扰。应调整前置条件和旧策略断言，不能回退已确认产品行为或跳过测试伪造全绿。
3. **统一写事务鉴权**：用户管理/资源任务已在事务内再次校验会话；部分旧 inventory/configuration 路由仍使用入口鉴权对象。如果权限在入口校验后、事务写入前被撤销，可能继续使用旧权限完成写入。宜统一锁顺序、写事务入口及撤权并发测试。
4. **数据库异常后的会话收尾**：远端会话巡检遇到数据库异常会停止 worker，但数据库恢复后对遗留 active 状态的收尾不完整。后续需要独立的故障恢复测试，避免在缓存回收重构中扩大状态机改动。
