# 集群日志与网页终端

## 更新部署

在项目目录执行（数据库迁移由 migrate 服务自动完成）：

```bash
docker compose --env-file .env -f deploy/compose.yaml up -d --build
```

保留原 `.env`、凭据加密密钥和数据库卷。本次迁移增加机器别名索引及远程会话元数据表。网页终端需要更新 web 和 api 两个服务，不能只更新前端。API 必须维持单实例、单 worker；API 重启会中断旧会话，需要主动重新连接。服务器上不应直接暴露 API 端口，继续通过同源 Nginx 入口访问。

## 使用步骤

1. 在机器资源详情填写“主机别名”，与 `dingo cluster status -sv` 的 Host 相对应。例如连接地址 `172.30.14.126` 增加别名 `dingo126`；地址、SSH 用户和凭据保持原配置。跨机器别名冲突会提示，并阻止自动选择连接目标。
2. 在集群详情刷新状态，然后点击服务行的“查看日志”。机器需要登记 SSH 密码并完成现有主机指纹确认。远程日志辅助程序要求 Linux `/proc` 和 `python3`。
3. 选择日志文件读取末尾 100、500 或 1000 行；点击“实时追踪”继续，暂停后可从记录位置恢复。轮转、截断或缓冲丢弃会显示提示。单次末尾读取最多 1 MiB；浏览器缓冲最多 5000 行或 5 MiB。
4. 关键词只按字面量过滤已加载内容。“下载当前内容”下载缓冲区原文；“下载远程文件”最多 100 MiB，读取开始时的固定长度。文件列表标识保留 15 分钟，过期后刷新列表。
5. admin 在集群详情选择管理机器或已匹配服务机器，打开新标签页。确认机器名、地址、端口及 SSH 用户后才建立终端连接。支持输入、尺寸调整、Ctrl+C 和断开；不会自动重连、重放输入或执行诊断命令。

日志读取使用集群登记的执行用户；与 SSH 用户不同则先尝试免密 sudo，确需密码时显示对应账号并进行一次性认证。终端直接使用机器的 SSH 用户，具有该系统用户真实权限，可由管理员自行输入 sudo/su；并非限制在当前集群范围内的命令行。日志查看器仅能读取该服务日志目录内的普通文件，不能执行终端命令。

## 权限和会话

- 所有登录用户仍可查看机器及集群信息。
- 日志正文仅 admin，或同时创建该集群与目标机器的用户可读。
- 完整终端仅 admin。终端和日志订阅均绑定创建它的登录会话，ID 本身不授予访问权；admin 可关闭其他用户的会话。
- 退出登录、禁用、删除、重置密码、机器/集群版本变化或服务日志路径变化，最迟在下一次权限检查时关闭连接（当前周期 2 秒）。主机密钥变化会使旧授权失效，需要核验指纹。
- SSH 密码仍沿用已有加密存储。临时 sudo 密码、终端输入/输出和日志正文不写入数据库或审计；有限读取放在有期限的内存缓冲，下载放在权限受限的临时目录，取消、失败或到期清理。
- 审计记录会话操作者、目标、类型、开始/结束及错误原因；下载记录文件标识和字节数，不提供逐条终端命令录像。
- 关闭平台连接会关闭 SSH 通道并回收平台工作进程；用户自行启动的远程后台任务不保证随之结束。

`.env.example` 中 `PLATFORM_REMOTE_*` 提供连接、读取、下载、空闲、最长时长和并发限制。默认连接 15 秒，读取 30 秒，下载 120 秒，终端空闲 15 分钟，终端/追踪最长 2 小时；每用户终端 2 个、同类日志操作 4 个，每机器远程操作 4 个。等待一次性密码的会话也占用配额，最多尝试 3 次。输出消费过慢会明确断开，不伪装完整内容。

## 手工验收

- 地址使用 IP、服务 Host 使用别名时能关联；制造别名冲突后不能连接。
- 普通用户能读取自己集群和自己机器的日志；换成别人的机器或集群后禁止读取，且不能进入终端。
- 文件列表、末尾读取、字面量关键词、追踪/暂停/恢复、轮转提示和两种下载正常。
- 终端确认取消不会连接；确认后输入及 Ctrl+C 正常；刷新页面、主动断开、退出登录后连接释放。
- 同一会话不能从另一登录或另一个标签页重复附着；跨源 WebSocket 拒绝。
- 测试过程中变更机器别名/凭据或集群日志路径后，旧连接关闭；重新选择目标后才能继续。

自动验证仅使用隔离数据库、本机 SSH 服务及临时目录，未在真实 DingoFS 集群执行任何命令。

## 接口

- `GET /api/v1/clusters/{id}/remote-targets`：当前服务与机器映射，以及可读权限。
- `POST /api/v1/remote-sessions`：创建 `files`、`read`、`download`、`log-follow` 或 `terminal` 会话；终端需要 `confirmed: true`，日志目标由服务端解析。
- `GET /api/v1/remote-sessions/{id}`：查询状态；有限读取的正文从短期内存返回。
- `POST /api/v1/remote-sessions/{id}/authenticate`：提交服务器颁发的一次性密码挑战。
- `GET /api/v1/remote-sessions/{id}/download`：在有效权限下下载已完成的文件快照。
- `DELETE /api/v1/remote-sessions/{id}`：关闭并撤销会话。
- `WS /api/v1/remote-sessions/{id}/stream`：同源、Cookie 验证、单次附着；日志流不接受终端输入。

文件列表会话在选文件、读取及追踪期间保留，刷新列表或离开页面才撤销。服务端再次核验文件标识所属的服务、集群、机器版本和登录会话，浏览器不能提交绝对路径替代文件标识。

代理配置回归可单独运行（Linux、本机 Docker 和已构建 web 镜像）：

```bash
PLATFORM_TEST_WEB_IMAGE=dingofs-test-platform-web:latest \
  python3 -m unittest discover -s deploy/tests -v
```

该检查使用临时 Nginx 和本机模拟接口，验证创建会话的 POST 不发生尾斜杠跳转、保留请求正文与外部端口，同时检查查询和 WebSocket 升级转发。不会连接真实 SSH 或 DingoFS 集群。
