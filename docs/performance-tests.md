# 性能测试

入口：侧边栏「性能测试」，或 `/#/performance`。

1. 在机器资源中登记 SSH 凭据，使用「测试工具」部署 dtt。旧安装请执行一次更新：新版会同时部署匹配的性能入口与报告脚本，避免旧镜像不识别新参数。
2. 新建测试，选择机器及目标目录（普通目录不存在时自动创建，权限不足时尝试 sudo 创建并授权）。普通目录可用于本地磁盘或其他存储；挂载目录模式会在测试前和运行中检查挂载状态。第一版不支持裸设备测试。
3. 勾选 fio、elbencho 中一个或两个工具，各自配置参数。每个参数可选择多个值，自动生成笛卡尔积组合，每批最多256个候选组合。常用值点击添加只读标签，标签按数值或实际容量升序排列，点击标签的×删除。自定义入口每次添加一个值。每台机器同时只能运行一个平台性能任务，场景按顺序运行；普通场景失败继续其余场景，整批最终记为失败；取消、超时或挂载丢失停止后续场景。
4. 预览执行计划，查看逐场景参数、命令、场景数量和累计保留数据量后启动。目标目录中生成 `platform-performance-<任务ID>/<场景ID>/` 独立目录，原有文件不会被清理；读测试先生成专属数据。
5. 任务列表和详情显示场景阶段、已完成轮次、进度、日志及错误；可取消自己的任务，管理员可取消全部任务。浏览器关闭不影响任务；平台 API 重启后恢复采集，不重复启动。
6. 结束后在同一任务查看逐场景结果表和网页报告、JSON摘要、原始附件和远端报告路径。均值仅统计成功测量轮次，不混合不同参数组合数据。报告副本保存在平台数据库中。

## 口径与限制
- 单客户端测试；尚未接入其他 dtt 工具和预置 AI Storage 场景矩阵。
- 文件数量是全局总数。可用「文件大小×数量」或「总量÷数量」定义数据集；轮次复用同一场景的数据，不按轮次倍增空间。
- 使用机器资源登记的 SSH 用户；优先使用平台托管 dtt，未找到时查找该用户 PATH 和 ~/.local/bin/dtt；不隐式安装工具、不修改 dtt 全局配置、不清理系统缓存。
- 最多100轮，单任务总超时1～1440分钟。空间预检查为各场景保留数据量之和，不能代替底层文件系统quota检查。
- API状态未知时保留机器互斥并继续采集，不把失联任务显示为成功。远端监督进程丢失时需要核实进程和容器后人工处理记录。
- 详情保存最近128KiB控制台输出；完整日志位于任务远端目录。每个场景收集最多16MiB附件、单文件最多4MiB，整批序列化附件最多32MiB；超出附件留在远端。
- HTML报告采用独立sandbox，不授予平台页面身份；所有登录用户可查看任务和报告，只有机器拥有者和管理员可发起测试。

## 组合规则
例如并发选择 `1` 和 `4`、Block选择 `4KiB` 和 `1MiB`、读写选择顺序读/顺序写，生成8个场景。Direct I/O、文件大小或总大小、数量、轮次、队列深度也支持多值。读比例只在混合读写场景中展开。单位相等和重复的参数组合去重；任一非法组合会阻止提交并给出参数及原因，不静默跳过。修改参数会使旧预览失效，需要重新预览。

最新参数组合验收：8/8 场景、每场景2轮通过，任务 `8a1bc5d0-6b47-4c7f-b623-baf06c3d776a`。详见 [验证记录](performance-matrix-verification.md)。

## 任务列表与重跑
任务表格支持按任务名、机器、目标目录搜索和按状态筛选，展示工具/场景数、进度、耗时和创建时间。点击“查看报告”打开逐场景结果表；执行日志默认折叠。
已结束且有管理权限的任务可点击“重跑”，确认后复用原始具体场景、目录和总超时，创建独立的新任务、数据子目录和报告，原记录保留。运行中或状态未确认的任务不可重跑；目标机器维护、归档、正在测试或部署工具时拒绝新任务。重跑按当前机器登记的连接信息执行，不重新展开原矩阵。

## 可选数据清理
新建任务可勾选“测试完成后清理测试数据”，默认关闭。只在全部场景通过后清理该任务 `platform-performance-<任务ID>` 数据目录，报告和日志始终保留；测试失败、取消或超时保留数据。清理失败会显示具体原因。重跑继承此选项。清理不减少执行前所需的累计数据空间，因为要等全部场景通过后才开始清理。

## mdtest 元数据测试

性能测试新建页可添加 mdtest，与 fio、elbencho 一起运行。复用 dtt 的
`ai-storage-t03` 场景，支持 MPI 进程数、文件总数、目录布局（独立 / 共享）和轮次的多选组合。
文件总数是单机全局数量，必须能被进程数整除；不使用 Direct I/O、文件大小或块大小。

每轮依次创建空文件、stat 查询、删除文件。删除属于测试阶段，与任务最后的清理选项无关。
数据量显示 0 B 只代表文件内容为空，仍会占用 inode 和元数据空间。
报告按操作分别展示 ops/s 算术均值，并提供 MPI 进程数和目录布局的分组柱状图、
各阶段原始日志和 JSON 附件。缺失阶段、异常速率和轮次不足不能判为成功。

首次使用请在目标机器详情执行“一键部署/更新 dtt”。
本次 dtt 运行时修复了 mdtest 4.1 汇总行无冒号的解析兼容性，
以及多进程单机测试的 MPI localhost slot 配置；更新会复制元数据运行时，
无需为这些脚本修复重新构建大镜像。

验证：本机临时目录中 1/2 MPI 进程 × 独立/共享目录，
每组合 8 个文件、2 轮，4 个组合均成功；结束后清理任务数据，保留报告。
这用于链路验证，不代表大规模性能结论。

### mdtest 自定义场景

平台根据镜像内 `mdtest -h`（当前 4.1.0+dev）提供阶段、目录树、数据读写、任务数扫描、输出和 I/O 模块参数。MPI 进程数、总条目数、测量轮次、目录布局保持常用入口，其他参数按需展开。数值参数可以添加多个候选值，自动生成组合。

- `-i` 对应测量轮次，`-u` 对应独立目录布局。`-n` 是**每进程**条目数，显式设置时覆盖平台的总条目数；`-I` 是每目录条目数，与 `-n` 互斥。
- 平台默认 `-F` 文件测试；关闭后同时测试文件和目录，勾选 `-D` 自动关闭 `-F`。
- 未指定 `-C/-T/-E/-r` 时，mdtest 执行全部阶段。仅查询/读取/删除不会自动准备数据；各场景仍使用独立目录。取消“清理数据”不等于禁用 mdtest 删除阶段。
- `-d`、CSV 和状态文件路径必须是任务目录内的相对路径；`-d` 支持 `@` 分隔多个相对目录。前后置命令在测试容器内执行，作为单独参数传递。
- 当前 API 为 POSIX / DUMMY；DUMMY 为模拟测试。帮助中列出的 MPIIO / MMAP 模块选项保留说明，当前 API 不启用这些模块。
- 预览展示 dtt 命令和 mdtest 命令。每个场景生成独立 `.mdtest`，执行 `dtt -t mdtest -s custom --custom-dir <场景目录>`，不修改用户全局 custom 配置。
- 报告保存原生命令、日志、JSON、HTML。速率与耗时使用不同单位；任务数扫描分别展示结果，不跨不同任务数取平均。耗时输出精度造成的 0 保留为 0。

目标机需要更新 dtt 启动器以支持 `--custom-dir`。在机器详情执行“一键部署/更新”即可，不需要重新编译 mdtest。旧启动器会拒绝未知选项，不会误运行其他 custom 目录。
