# 集群资源管理：部署与验收

## 部署

本次新增两张表，必须先迁移再重启服务。保留原 `.env` 和凭据加密密钥。

```bash
cd /mnt/disk5/daigy/dingofs-test-platform
docker compose --env-file .env -f deploy/compose.yaml build api web migrate
docker compose --env-file .env -f deploy/compose.yaml run --rm migrate
docker compose --env-file .env -f deploy/compose.yaml up -d --no-deps api web
```

`PLATFORM_RESOURCE_OPERATION_TIMEOUT` 默认 600 秒，可在 `.env` 设置 10–3600 秒。任务到期会在读取状态时标为中断，不自动重试写操作。总超时包含本轮的所有成员步骤；用户切换认证后继续未完成步骤。

## 使用前提

- 集群已发现并成功采集状态，具有正确 MDS 地址。
- 执行机器已登记 SSH 密码；使用目标用户的登录环境查找 dingo。
- 文件系统、缓存命令需要支持 `fs`/`cache` 子命令的 dingo 版本；目录统计和回收站恢复需要 `dingo-mds-client`（可填绝对路径）。
- 缓存/客户端运行机器需要相应 dingo-cache/dingo-client、FUSE 和权限；RDMA 仅在对应机器具备设备时开启。
- 远程 helper 使用 Python 3；缓存停止优先使用 Linux pidfd。旧 Python 缺少 pidfd 接口或内核返回 ENOSYS 时，发送前重新核验 PID、启动时间、可执行文件及完整启动参数，再向该 PID 发送一次 SIGTERM，最多等待 30 秒。进程仍存活则报告失败，不自动 SIGKILL。兼容路径无法像 pidfd 一样原子消除身份核验与发送信号之间的 PID 复用竞态；支持 pidfd 的机器继续使用 pidfd，权限错误不会降级绕过。

## 页面

进入集群详情的“资源管理”，打开独立页面。一级导航为文件系统、缓存组、挂载点、操作记录，每次只显示选中的区域。文件系统通过二级导航选择基础操作、文件系统配额、目录配额、回收站、目录统计，再选择操作、填写参数并执行。当前功能只展示最近一次结果；完整历史在“操作记录”中按目标关键词和状态筛选，历史记录默认折叠。缓存组与挂载点用可搜索、可按状态筛选的表格展示，行内提供常用操作；点击日志会预选对应挂载点。切换一级导航不发起远端命令，已有任务继续查询进度，顶部提供“查看进度”入口。查询操作也通过任务读取远端，所有登录用户可查看已保存的结果；远端执行要求管理员或集群创建者，额外机器还需有机器管理权限。

- 文件系统：查询全部或指定文件系统；S3/RADOS 创建和删除。创建后的实际名称以命令返回/重新查询为准。 点击“文件系统详情”或“删除文件系统”自动执行文件系统列表查询，使用查询到的名称填充下拉框；支持刷新列表。列表加载中、查询失败、无文件系统或尚未选择时禁止提交，删除仍需确认。
- 配额：文件系统及目录配额的设置、查询、清除。容量单位 GiB；文件系统清除实际设置 capacity/inodes 为 0。
- 回收站：配置查询、保留天数修改、按文件系统 ID/小时范围恢复，可选择恢复原路径。
- 目录统计：info、summary、开启/关闭、同步，可选递归或修复。
- 缓存组：创建 1–32 个成员，可跨多台有权限的机器。缓存基础目录下按成员 UUID 隔离，记录 RDMA 参数与进程身份。组由成员注册形成；停止记录的进程并保留成员登记。「删除缓存组成员登记」从查询结果选择单个成员，显示组名、成员 ID、地址和状态；没有可用查询结果时先点击「刷新缓存成员列表」。执行前再次检查成员状态，离线或 Unknown 成员可删除登记，在线成员需先停止并等待离线。
- 挂载：填写机器、用户、文件系统、挂载目录，可选子目录、缓存组和 RDMA。拒绝覆盖现有挂载。卸载使用平台记录并核对当前挂载身份。
- 客户端日志：选择挂载记录，先执行“客户端日志”列出文件，再填写文件名读取最近 100/500/1000 行；重复查询即可刷新。

缓存组停止及挂载卸载只作用于平台管理记录；删除缓存成员登记支持查询到的外部成员，由集群管理入口执行 `dingo cache member delete <member_id>`，不会接管或停止外部进程。旧版本已保存的整组删除任务仍使用原有平台进程身份校验。删除缓存成员不会删除缓存数据目录；卸载不会删除挂载目录或日志。远程状态和日志位于对应用户私有的 `/tmp/dingofs-platform-resources-<user>/` 下，不能手工修改其记录。

## 验收清单（请在可用测试环境进行）

1. 普通用户可读他人集群记录，无法执行他人集群操作，也无法选择他人机器执行任务；管理员可管理全部。
2. 用测试存储创建文件系统，查询确认实际名称；设置/读取/清除两类 quota，查询/修改回收站配置和目录统计。
3. 在两台机器各创建一个缓存成员，检查组列表；停止并删除。确认结果包含各成员步骤，其他缓存进程没有被操作。
4. 创建测试挂载，写入测试数据后查看日志，检查挂载状态并卸载。再次卸载应幂等；旧记录不能卸载同路径后来创建的新挂载。
5. 制造一个错误监听端口或不可用目标：任务报告部分失败，保存已创建的记录，允许安全停止/删除；不要直接重新提交文件系统创建来猜测结果。
6. sudo 要求密码时，填写提示的系统账号密码。取消和密码失败不会重复已成功的缓存成员步骤。
7. 按确认的展示要求，文件系统详情（fs.get）返回的 S3 AK/SK 保留原值，随查询结果保存，所有可查看集群的用户均可查看。旧的已脱敏结果不能还原，需重新查询。列表、回收站及其他操作保持原有脱敏；SSH、sudo 密码和其他存储凭据仍不显示。用于执行操作的临时存储凭据在任务终态移除。

开发验证使用本机临时 PostgreSQL、mock SSH 和本地假命令，没有连接或变更真实集群；以上环境验收需部署后执行。

## 通配符批量删除文件系统

基础操作 → 通配符批量删除会自动查询文件系统列表。使用 Shell 通配符完整匹配名称（例如 `vdbench*`）；支持 `*`、`?`、字符集合和范围，不支持花括号展开或扩展通配符，可取消勾选；确认框展示固定名单，每批最多 100 个。执行中不会加入新匹配项。逐项展示成功或失败；已完成命令的失败不阻止后续删除，连接中断、超时等停止执行，未执行项需重新查询确认。此操作沿用集群管理权限和二次确认。

## 存储配置与创建文件系统

侧栏“存储配置”统一登记 S3/RADOS 连接参数。创建者及管理员可以编辑、启停、删除配置，其他登录用户可查看连接信息并选择使用。密钥加密保存，编辑时留空保留原值。删除配置不会删除真实存储或已有文件系统。

创建文件系统时选择启用配置，核对连接摘要后确认提交。没有可用配置时先登记；配置被更新时重新选择。后台使用提交时的连接参数与凭据快照，后续配置变化不影响已提交操作。表单及操作参数不发送或保存明文凭据。

此功能发布需要执行最新数据库迁移，随后更新 api 和 web。

## 配额、回收站与目录统计的文件系统选择

进入资源管理页面时自动获取一次文件系统列表；之后切换模块、页签或小功能均复用本次列表，只有点击“刷新文件系统列表”才重新获取。离开整个资源管理页面再进入或切换集群时重新初始化。所有操作使用名称下拉框，过滤含 `DELETED` 的名称。回收站恢复和部分目录统计命令的 `fs_id` 根据列表自动转换，不再手工输入。未选中、列表获取失败或 ID 缺失/超出精确整数范围时禁止提交；刷新列表清空之前的选择。

## 缓存组主列表

缓存组主表和页签数量以最近一次成功的「缓存组与成员列表」查询为依据，合并 MDS 的 `group_names` 和成员登记中的组名。已停止但尚未删除登记的组保留展示；未实际注册的创建失败记录、已删除的平台记录不作为真实缓存组展示。未分组成员仍可在成员删除选择器中处理。创建失败及恢复过程保留在操作记录中，不删除审计信息。

查询失败时显示失败原因，不用平台本地创建记录充当查询结果。还没有查询时，平台托管记录单独说明其性质；外部组仅展示成员信息并提供选择成员删除入口，只有成员身份与平台记录匹配的组才显示停止进程按钮。

### 缓存成员通配符批量删除

- 缓存组操作选择“通配符批量删除缓存成员”，支持以 Shell 通配符匹配缓存组名或成员 ID（例如 `vdbench_cache_group*`），可取消勾选，单批最多 100 个成员。
- 在线成员不可勾选。提交时确认固定成员 ID 名单；服务端逐项重新查询状态后删除登记，保留缓存数据目录，不停止进程。
- 明确完成的单项失败记录后继续下一项；连接中断或超时停止后续执行，展示成功、失败及未返回结果的成员。失败批次中已成功删除的成员也从旧列表候选项移除。
- 前后端均需重新构建并启动，无数据库迁移。

缓存组列表行内“删除”直接打开确认框，列出组名及本次成员 ID 名单；取消不提交请求，确认后逐项删除该组成员登记。若含在线或不可删除状态成员、查询不可用、成员为空或超过 100 个，显示具体原因，不隐式删除部分成员。此操作保留缓存数据目录。

删除成功后，列表按已确认的逐项结果即时移除对应成员；组内成员全部删除时移除该组并更新导航数量。部分失败或未返回结果的成员继续展示。新的远端查询结果优先于旧删除记录，原本就为空的组不因本地删除过滤而消失。

### 创建失败进程日志

缓存组或客户端创建失败的结果中自动附带远端日志目录及日志末尾快照，页面直接展示“进程日志”。优先采集 launcher、fatal、error/stderr 和 stdout，最多 6 个普通文件，每个最多 80 行 / 16 KiB；跳过符号链接，保留截断标记并沿用敏感字段脱敏。无法读取日志时保留原始失败原因，另外展示读取错误。旧操作记录不自动补采；部署后的新失败操作开始保存快照。更新 api、web 即可，无数据库迁移。

### 同名缓存组新增成员

创建缓存组允许复用已有组名。每次创建生成独立成员 UUID、缓存子目录和平台管理记录；同组已有其他来源成员不再阻止创建或操作本次成员。新增成员不能复用其他成员已登记的监听 IP/端口；同一次请求的同机器监听端口也不能重复。停止及删除仍验证具体成员 UUID、地址和进程身份，不获得对同组其他成员的操作权。挂载路径同机唯一性不变。只需更新 api，无数据库迁移。

### 缓存成员自动端口检查与创建

创建表单默认自动端口模式，从 21000–29999 中选择；手动模式保留指定端口。选择机器预填监听地址和 SSH 用户，可自行修改。点击“检查并创建缓存组”只提交检查任务，读取 MDS 登记并在目标主机执行 IPv4/IPv6 通配 TCP bind 探测，不启动缓存进程；同时避开平台其他成员和有效任务预留端口。

点击“检查并创建缓存组”，检查成功后自动使用该清单创建，无需第二次点击或确认框。检查失败不启动成员；修改输入使当前清单失效。清单 10 分钟有效，绑定发起用户、集群与机器版本，一份清单只能用于一次创建（同 request_id 重放仍幂等）。新状态与记录使用现有 JSON 字段，无数据库迁移。

启动前再检查：自动模式遇占用重新分配，并在远端状态中先保存最终端口，结果回写平台；手动模式不换端口，显示冲突原因与建议。若探测后又被其他进程抢占，最终以进程成功监听和 MDS 上线为准；失败展示进程日志，不停止占用者，也不在启动结果未知时盲目重试。规划不会持续占有操作系统监听 socket。

旧 API 请求未填 port_mode 时保留手动模式。前后端需要一起更新。所有本地验证仅使用模拟远端执行或本地临时 socket，不启动真实缓存集群。

### 创建命令追踪

缓存端口检查、缓存成员创建及客户端挂载的结果中展示实际外部命令，包含 shell 转义后的参数和 PATH 解析到的程序位置；从 subprocess 执行点记录，不用表单推测命令。成功与失败均保存，最终自动调整的启动端口包含在命令内。重复就绪查询合并显示次数，区分尝试启动与已启动执行；后者不代表业务成功。沿用敏感字段脱敏，旧记录不补采。更新 api 与 web 后生效。

缓存创建任务成功完成后，有管理权限的当前页面自动发起一次 `cache.list`，通过现有查询结果更新组列表、成员与数量。同一个创建任务仅触发一次，不重复创建成员；失败或取消不触发自动查询，只读用户不发起远端查询。查询失败仍可使用现有刷新入口重试。仅更新 web 即可生效。

### 缓存组与成员分层操作

缓存组列表显示成员总数、在线数、离线数；“成员信息”展开整行成员表，显示 UUID、机器/地址、执行用户和状态。组级“停止全部成员”“删除全部成员”固定本次 UUID 名单；成员行提供独立停止、删除。添加成员预填所在组名。

停止按 UUID 跨所有创建记录找到唯一的进程管理记录，使用原资源身份执行。停止只结束进程，保留组成员登记；全部选中成员的进程确认退出后即完成，不再等待 MDS 成员状态变为离线；列表继续展示 MDS 实际状态，可能延迟更新。页面按最新查询状态禁用离线成员的停止按钮；组级停止跳过所有离线成员，全部离线或为空时禁用组级停止。平台创建记录缺失时使用下述外部成员流程；无法唯一定位执行机器或无权限时不冒充整组操作成功。

删除仍要求成员状态允许删除，保留缓存数据目录。组与成员停止/删除均需确认，一次最多 100 个成员。逐成员记录结果；明确返回的停止失败继续其他成员，通信超时等未知结果停止后续步骤。可在刷新后的成员行重试；停止/删除任务结束后自动查询缓存列表，包括部分失败的情况。无数据库迁移。

### 外部创建的缓存成员

非平台创建的成员同样支持成员级、组级停止及删除。停止前必须已成功查询成员列表；服务端按 UUID 读取成员 IP/端口，匹配机器资源地址、主机别名或已采集网卡 IP。唯一匹配且具备机器管理权限时开放停止；未匹配、匹配多台机器、未配置 SSH 密码或无权限均显示具体原因。删除离线登记不依赖平台创建记录，也不要求控制成员机器。

外部停止任务先通过集群管理入口重新核验 MDS 成员登记，再使用目标机器已有 SSH 凭据切换 root；sudo 需要密码时沿用操作认证表单。root 仅需 Python 3，无需安装 dingo。停止前校验 IP 属于本机，按可执行程序、UUID、组名、IP、端口及 MDS 启动参数唯一定位 dingo-cache，复用上述进程停止机制与进程启动时间校验后发送 SIGTERM；不按端口或进程名批量杀进程。参数不一致、重复进程、身份无法核验或被其他服务重新拉起均不得报告整组停止成功。保留成员登记及数据目录，进程退出后立即完成，不等待离线；MDS 状态可能延迟更新，持续在线时需检查启动服务的自动重启配置。

外部进程需在启动命令行中具有可核验的上述参数；仅由配置文件提供且命令行缺失关键身份参数时明确报错，不能猜测 PID。无需迁移数据库。

## 缓存组配置模板

支持独立的“缓存组配置”管理页面。参数目录来自 dingo-cache `main-fe4384a0b -hh`，包含 94 项参数、类型、说明和声明的默认值。模板在创建页复制为本次参数，可修改后检查并创建；端口计划持有不可变快照。成员目录、容量和 RDMA 以成员表单为准，身份和平台管理参数不可由模板覆盖。部署需迁移 `f8b9103462fc`，详见 [CACHE_PROFILES.md](CACHE_PROFILES.md)。

### 所有 DingoFS 操作的执行记录

资源操作（文件系统、配额、回收站、目录统计、缓存组、挂载点）统一记录实际子进程命令，成功和失败结果均展示已尝试的命令；重复的连续查询合并计数。敏感参数继续隐藏。缓存停止同时记录通过身份校验后发送的 SIGTERM，展示 `kill -TERM -- PID` 等价命令并注明实际系统调用 `pidfd_send_signal` 或 `os.kill`，不声称执行过 shell kill。身份校验失败或进程已不存在时，不伪造停止命令。

集群发现、状态采集、topology 查看及按服务/角色/整组的启动、停止、重启操作，使用与 SSH 执行相同的命令生成函数记录命令，展示集群环境变量、实际操作参数和 `--force`。历史任务未记录的命令不会补造；更新后的新任务生效。

### 成员离组、解锁与权重

组内成员行提供“离开缓存组”“解锁”“设置权重”；未分组成员提供解锁和权重。三种操作均要求集群操作权限及用户确认，执行记录显示实际命令。设置权重校验 uint32（0～4294967295）。离组保留成员登记与进程，完成后自动重新查询缓存组与成员，按实际返回结果显示为未分组，不伪造离组状态。操作前重新核对成员 UUID 唯一性及所属组，使用实时登记的 IP/端口；组归属变化时拒绝执行，提示刷新。

### 平滑停止与强制停止

缓存组和组内成员提供两个独立按钮：平滑停止发送 SIGTERM（等价 `kill PID`）；强制停止发送 SIGKILL（等价 `kill -9 PID`）。强制停止必须显式选择并确认，默认不会自动升级。两者均校验成员及进程身份、确认进程退出，不等待 MDS 离线。命令记录注明实际信号与系统调用方式。
